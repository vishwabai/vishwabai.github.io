Hyperparameters
The dials before training

Nine numbers that define the model's size, memory, and learning dynamics — before a single gradient is computed.

PARAM BUDGET VISUALIZER

batch_size = 32 — sequences processed in parallel per gradient update. More = stable gradients, more memory.

block_size = 128 — the context window: maximum tokens the model sees at once. Attention cost = O(T²).

▸ ARCHITECTURE SIZE

n_embd = 64 — every internal vector is exactly this wide.
n_head = 4 — 4 attention heads, each 16-dim.
n_layer = 4 — transformer blocks stacked.

head_size = n_embd / n_head = 16

Section 02 / 09

Data Pipeline
From raw text to tensor pairs

Character-level tokenization and a sliding window that extracts 128 training signals from every single window.

DATA FLOW
▸ TOKENIZER

Character-level: every unique character is one token. Shakespeare has 65 unique chars → vocab_size = 65. Simple and complete — no out-of-vocabulary tokens possible.

▸ SLIDING WINDOW
x = text[i : i+T] y = text[i+1 : i+T+1]

x and y are the same window, shifted by 1. At every position the model must predict the next char. 128 tokens → 128 training signals.

▸ 90 / 10 SPLIT

~900k tokens for training, ~100k held out for validation. Validation is never trained on — it measures generalisation. The split is a simple array slice, no shuffling.

PYTHON with open('input.txt') as f: text = f.read() chars = sorted(set(text)) # 65 unique chars vocab_size = len(chars) stoi = {c:i for i,c in enumerate(chars)} encode = lambda s: [stoi[c] for c in s] # "Hi" → [35,46] decode = lambda l: ''.join([chars[i] for i in l]) data = torch.tensor(encode(text), dtype=torch.long) # (1M,) n = int(0.9*len(data)) train_data, val_data = data[:n], data[n:] def get_batch(split): d = train_data if split=='train' else val_data ix = torch.randint(len(d)-block_size, (batch_size,)) x = torch.stack([d[i:i+block_size] for i in ix]) # (32,128) y = torch.stack([d[i+1:i+block_size+1] for i in ix]) # (32,128) shifted+1 return x.to(device), y.to(device)
Section 03 / 09

Attention Head
Tokens learning to listen

Query asks, Key offers, Value delivers. Dot-products decide who gets heard. The causal mask ensures nothing can see the future.

SCALED DOT-PRODUCT ATTENTION
▸ Q · K · V

Query — "what am I looking for?"
Key — "what do I contain?"
Value — "what do I share if attended to?"
Three separate Linear(64→16) projections, no bias.

▸ SCALED DOT PRODUCT
score = Q · Kᵀ / √dₖ

Without √dₖ = √16, large dims push scores into softmax's flat region (near-zero gradients). The scaling keeps variance stable regardless of head size.

▸ CAUSAL MASK

torch.tril makes a lower-triangular matrix of 1s. Upper triangle positions → −∞ → 0 after softmax. Position 5 cannot see 6, 7, … — enforces left-to-right generation.

PYTHON class Head(nn.Module): def __init__(self, hs): # hs = 64//4 = 16 super().__init__() self.q = nn.Linear(n_embd, hs, bias=False) self.k = nn.Linear(n_embd, hs, bias=False) self.v = nn.Linear(n_embd, hs, bias=False) self.register_buffer('mask', torch.tril(torch.ones(block_size,block_size))) self.drop = nn.Dropout(dropout) def forward(self, x): # x: (B, T, 64) B,T,C = x.shape q,k,v = self.q(x), self.k(x), self.v(x) # each (B,T,16) sc = q @ k.transpose(-2,-1) * k.shape[-1]**-0.5 # (B,T,T) sc = sc.masked_fill(self.mask[:T,:T]==0, float('-inf')) w = self.drop(F.softmax(sc, dim=-1)) return w @ v # (B,T,16)
Section 04 / 09

Multi-Head Attention
Four lenses on the same sequence

Independent heads, each 16-dimensional, specialize in different relationship types. Concatenate then project back — mixing their findings.

MULTI-HEAD ATTENTION
▸ WHY MULTIPLE?

One head can only attend to one "type" of pattern. Four heads let the model simultaneously track syntax, co-reference, semantics, and positional context — each head specializes emergently during training.

▸ DIMENSION MATH
head_size = 64 / 4 = 16 cat([h₁,h₂,h₃,h₄]) → (B,T,64) proj: Linear(64,64) → (B,T,64)
▸ PROJECTION

After concatenation, proj Linear(64→64) lets the model mix information across heads. Without it, heads are isolated — their outputs are just stacked, not combined.

PYTHON class MultiHead(nn.Module): def __init__(self, n_head, hs): super().__init__() self.heads = nn.ModuleList([Head(hs) for _ in range(n_head)]) self.proj = nn.Linear(n_head*hs, n_embd) # mix across heads self.drop = nn.Dropout(dropout) def forward(self, x): out = torch.cat([h(x) for h in self.heads], dim=-1) # (B,T,64) return self.drop(self.proj(out))
Section 05 / 09

Feed-Forward Network
Per-token computation

After attention mixes across tokens, the FFN processes each token in isolation. Expand 4×, activate with GELU, contract. This is where most parameters live.

FEED-FORWARD NETWORK
▸ 4× EXPANSION

64 → 256 → 64. The expansion factor of 4 is a GPT standard. Most parameters live here: 64×256 + 256×64 = 32,768 per FFN × 4 blocks = 131k params — 65% of the whole model.

▸ GELU ACTIVATION
GELU(x) = x · Φ(x)

Smoother than ReLU: allows small negative values through. Φ(x) is the Gaussian CDF. In practice ~0.1 nats better loss on language tasks for no extra compute.

▸ POSITION-INDEPENDENT

Unlike attention, FFN has no cross-token mixing. Each of the T tokens is transformed identically in isolation. Think of it as: attention = routing, FFN = thinking.

PYTHON class FFN(nn.Module): def __init__(self): super().__init__() self.net = nn.Sequential( nn.Linear(n_embd, 4*n_embd), # 64 → 256 expand nn.GELU(), # smooth nonlinearity nn.Linear(4*n_embd, n_embd), # 256 → 64 contract nn.Dropout(dropout)) def forward(self, x): return self.net(x)
Section 06 / 09

Transformer Block
Attention + FFN + residuals

The repeating unit stacked 4 times. Pre-LayerNorm and residual connections are the two decisions that make deep transformers trainable.

TRANSFORMER BLOCK
▸ RESIDUAL CONNECTION
x = x + SubLayer(LN(x))

The x + creates a gradient highway — gradients flow back through the addition directly, bypassing the sub-layer. Without it, 4+ layers cannot be trained: gradients vanish.

▸ PRE-LN vs POST-LN

Original transformer used Post-LN (norm after). GPT-2 and this code use Pre-LN (norm before). Pre-LN is more stable at init and in early training — loss doesn't spike as badly with bad seeds.

▸ LAYER NORM
LN(x) = γ·(x−μ)/σ + β

Normalize each token's 64-dim vector to mean≈0, std≈1, then apply learned γ (scale) and β (shift). Only 128 params per LN, but critical for stable gradients in deep stacks.

PYTHON class Block(nn.Module): def __init__(self): super().__init__() hs = n_embd // n_head self.attn = MultiHead(n_head, hs) self.ffn = FFN() self.ln1 = nn.LayerNorm(n_embd) self.ln2 = nn.LayerNorm(n_embd) def forward(self, x): x = x + self.attn(self.ln1(x)) # residual + attention x = x + self.ffn(self.ln2(x)) # residual + FFN return x
Section 07 / 09

MicroGPT Model
Embeddings → blocks → logits

The complete architecture: two lookup tables, four stacked blocks, a final LayerNorm, and a linear head projecting to 65 character probabilities.

FULL FORWARD PASS
▸ TWO EMBEDDINGS

tok_emb [65×64] — character identity.
pos_emb [128×64] — sequence position.
Added together: "what I am" + "where I am". Both are learned from scratch during training.

▸ PARAMETER BUDGET
ComponentParams
tok_emb + pos_emb12,352
4 × Block~161k
ln_f128
lm_head4,160
Total~200k
▸ LM HEAD + LOSS

Linear(64→65) outputs one logit per character at every position. Cross-entropy loss: flatten (B,T,65) → (B×T,65), compute −log P(correct). Random: loss≈4.17. Trained: loss≈1.6.

PYTHON class MicroGPT(nn.Module): def __init__(self): super().__init__() self.tok_emb = nn.Embedding(vocab_size, n_embd) # 65×64 self.pos_emb = nn.Embedding(block_size, n_embd) # 128×64 self.blocks = nn.Sequential(*[Block() for _ in range(n_layer)]) self.ln_f = nn.LayerNorm(n_embd) self.lm_head = nn.Linear(n_embd, vocab_size, bias=False) # 64→65 def forward(self, idx, targets=None): B,T = idx.shape x = self.tok_emb(idx) + self.pos_emb(torch.arange(T, device=device)) x = self.ln_f(self.blocks(x)) logits = self.lm_head(x) # (B,T,65) loss = None if targets is not None: loss = F.cross_entropy(logits.view(-1,vocab_size), targets.view(-1)) return logits, loss
Section 08 / 09

Training Loop
Five lines, 5000 times

Forward → loss → zero_grad → backward → step. Each iteration nudges 200k parameters toward predicting Shakespeare. Loss drops from 4.17 to ~1.6.

TRAINING DYNAMICS
▸ CROSS-ENTROPY LOSS
L = −log P(correct token)

Random over 65 chars → L = log(65) ≈ 4.17. Trained → L ≈ 1.6. Loss measures surprise. Each halving ≈ 2× more confident about the next character.

▸ ADAMW OPTIMIZER
θ = θ − lr·m̂/(√v̂+ε) − wd·θ

Adam with weight decay. Maintains momentum m and variance v per parameter. Adapts step size — common parameters get smaller updates. wd=0.01 penalizes large weights.

▸ BACKPROP ORDER

Critical sequence: zero_grad → backward → step. Never swap. set_to_none=True frees gradient memory rather than zeroing (faster). backward() fills .grad. step() uses them.

PYTHON model = MicroGPT().to(device) opt = torch.optim.AdamW(model.parameters(), lr=lr) for step in range(max_steps): xb, yb = get_batch('train') _, loss = model(xb, yb) # forward pass opt.zero_grad(set_to_none=True) # ① clear old grads loss.backward() # ② compute ∂L/∂θ opt.step() # ③ θ = θ − lr·grad if step % eval_every == 0: print(f"step {step}: loss={loss.item():.4f}")
EXPECTED LOSS CURVE

Step 0: ~4.1 → Step 500: ~2.5 → Step 2000: ~1.9 → Step 5000: ~1.6 — each halving means the model is roughly 2× more certain about the next character. Training on CPU takes ~2 minutes.

Section 09 / 09

Generation
The model talks to itself

Autoregressive sampling: feed the model its own output, one token at a time, until done. Temperature controls creativity. Context window limits memory.

AUTOREGRESSIVE GENERATION
▸ AUTOREGRESSIVE

Each generated token is appended and fed back as input for the next step. The model conditions on its own outputs — this is the fundamental architecture of GPT, LLaMA, Claude, and every major LLM.

▸ SAMPLING vs GREEDY
probs = softmax(logits / T) T < 1 → focused (repetitive) T = 1 → standard sampling T > 1 → creative (chaotic)
▸ CONTEXT CROP

idx[:, -block_size:] — once the sequence exceeds 128 tokens, the oldest are dropped. The model literally cannot see beyond its context window — this hard limit is why longer contexts matter.

PYTHON def generate(self, idx, max_new=200): for _ in range(max_new): idx_c = idx[:, -block_size:] # crop to context logits, _ = self(idx_c) probs = F.softmax(logits[:,-1,:], dim=-1) # last pos only nxt = torch.multinomial(probs, num_samples=1) # sample idx = torch.cat([idx, nxt], dim=1) # append → repeat return idx # kick off from newline seed ctx = torch.zeros((1,1), dtype=torch.long, device=device) print(decode(model.generate(ctx, 500)[0].tolist()))
WHAT TO TRY NEXT

1. Temperature: divide logits by 0.8 for more focused output. 2. Scale: n_embd=256, n_layer=6 → ~10M params, much better prose. 3. RoPE: replace pos_emb with rotary embeddings (LLaMA). 4. SwiGLU: gated FFN for ~0.2 nats lower loss. 5. BPE: swap character tokenizer for tiktoken GPT-2 encoding.
