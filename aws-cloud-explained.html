01 — The basic idea

Cloud computing, in one sentence

Instead of buying physical servers and racking them in a room, you rent computing power from AWS's data centers and pay only for what you use — like electricity, not like buying a generator.

On-premise

You own everything

Buy servers, install them, cool them, patch them, replace them when they die. Capacity is fixed — guess wrong and you either waste money or run out.

Cloud (AWS)

You rent capacity

Click a button (or call an API) and a server exists in minutes. Need more at 9am, less at midnight? Scale up and down automatically. AWS owns the hardware risk.

02 — Where it physically lives

Regions, Availability Zones, Edge Locations

AWS's infrastructure is organized geographically so you can put your application close to your users and survive a data center failure.

Region — e.g. ap-south-1 (Mumbai)
Availability Zone A
isolated data center cluster
Availability Zone B
independent power, network
Availability Zone C
few ms apart from A & B

A Region is a geographic area (Mumbai, Frankfurt, N. Virginia...). Each Region has multiple Availability Zones (AZs) — physically separate facilities. Edge Locations are smaller sites worldwide used by CloudFront to cache content near end users.

03 — The four pillars everyone starts with

Compute, Storage, Database, Networking

Nearly every AWS architecture is built from these four categories. Learn these well before anything else.

Compute

EC2

A virtual machine in the cloud. You choose CPU, RAM, OS, and pay per second it runs. This is the closest thing to "a regular server."

Compute

Lambda

Run a function without managing any server. AWS runs your code only when triggered, then shuts it down. You pay per execution, not per hour.

Storage

S3

Object storage for files — images, backups, logs, datasets. Virtually unlimited, durable (99.999999999%), accessed over HTTPS.

Storage

EBS

A virtual hard disk attached to one EC2 instance — like the C: drive of your cloud server.

Database

RDS

Managed relational databases (PostgreSQL, MySQL, etc). AWS handles backups, patching, and replication for you.

Database

DynamoDB

A managed NoSQL key-value database built for huge scale and single-digit-millisecond response times.

Networking

VPC

Your own private, isolated network inside AWS — subnets, route tables, and firewalls you control.

Networking

Route 53 & CloudFront

Route 53 is DNS (domain → IP). CloudFront is a global content delivery network that caches content near users.

04 — Who's allowed to do what

IAM — Identity and Access Management

Every single thing in AWS is gated behind a permission check. IAM is the system that decides who (or what) can do what.

User

A person

A human with login credentials, usually with multi-factor authentication enabled.

Role

A borrowed identity

Temporary permissions assumed by a service (like EC2 or Lambda) so it can call other AWS services securely — no hardcoded keys.

Policy

The rulebook

A JSON document stating exactly which actions are allowed or denied on which resources.

Golden rule: least privilege — grant only the permissions a user or service actually needs, nothing more.

05 — Intermediate concepts

Making applications reliable and elastic

Once a single EC2 instance isn't enough, these are the next concepts you reach for.

Elastic Load Balancer (ELB)

Spread traffic across many servers

Sits in front of multiple EC2 instances and routes incoming requests so no single server is overwhelmed, and unhealthy instances are skipped.

Auto Scaling Group

Grow and shrink automatically

Defines minimum, desired, and maximum instance counts. AWS launches new servers under load and terminates extras when traffic drops — you stop paying for idle capacity.

CloudWatch

See what's actually happening

Collects metrics, logs, and alarms across every service. Auto Scaling decisions are usually driven by a CloudWatch alarm (e.g. "CPU > 70%").

Multi-AZ Deployment

Survive a data center outage

Run duplicate resources in two or more Availability Zones so the failure of one facility doesn't take your application down.

06 — Advanced patterns

Containers, serverless, and shipping code automatically

Containers

ECS & EKS

Run Docker containers at scale. ECS is AWS's own orchestrator; EKS is managed Kubernetes. Both schedule containers across a fleet of servers (or serverless Fargate).

Serverless

Fargate

Run containers without managing the underlying EC2 servers at all — point at an image, AWS handles the compute layer.

Event-driven

SQS, SNS, EventBridge

Decouple services with queues (SQS) and pub/sub messaging (SNS, EventBridge), so one part of the system failing doesn't cascade into the rest.

Delivery

CI/CD — CodePipeline / CodeBuild

Automate the path from git push to a live deployment: build, test, and release without manual steps.

Infra as Code

CloudFormation / CDK / Terraform

Describe your entire infrastructure in code/config so it's reproducible, versioned, and reviewable — instead of clicking through a console.

Cost

Reserved & Spot Instances

Commit ahead of time (Reserved) for a discount, or bid on spare capacity (Spot) for up to ~90% off — at the cost of it being reclaimable.

07 — Practical

Running your Python code on AWS

There's no single "right" way — it depends on whether your code runs occasionally, runs constantly, or needs a full server environment. Pick a tab.

AWS Lambda — run a Python function, no server to manage

Best for: short tasks, scheduled jobs, reacting to events (a file landing in S3, an API call). Free tier covers most hobby use.

  1. Open the AWS Console → Lambda → Create function → choose Author from scratch.
  2. Pick Runtime: Python 3.12, and create or reuse an execution Role.
  3. Paste your code into lambda_function.py, with a handler function:
def lambda_handler(event, context):
    print("Hello from AWS Lambda")
    return {"statusCode": 200, "body": "done"}
  1. Click Deploy, then Test to run it manually with a sample event.
  2. To run it automatically, add a Trigger — e.g. EventBridge (schedule, like cron), API Gateway (HTTP endpoint), or S3 (on file upload).
  3. Need external libraries (e.g. requests, pandas)? Package them as a Lambda Layer or zip them with your code before upload.

Or from your machine, using the AWS CLI:

pip install requests -t package/
cp lambda_function.py package/
cd package && zip -r ../function.zip . && cd ..

aws lambda create-function \
  --function-name my-python-fn \
  --runtime python3.12 \
  --handler lambda_function.lambda_handler \
  --role arn:aws:iam::<account-id>:role/lambda-exec-role \
  --zip-file fileb://function.zip

EC2 — a virtual server you fully control

Best for: long-running processes, apps needing a specific OS/GPU, or anything that doesn't fit Lambda's time/size limits.

  1. Console → EC2 → Launch Instance. Choose an Amazon Linux 2023 (or Ubuntu) AMI and instance type (e.g. t3.micro, free-tier eligible).
  2. Create or select a key pair (for SSH login) and a security group allowing inbound SSH (port 22) from your IP.
  3. Launch the instance, then connect:
ssh -i my-key.pem ec2-user@<public-ip-address>
  1. Install Python (Amazon Linux ships with it; otherwise: sudo yum install -y python3 python3-pip).
  2. Upload your script (or git clone it) and run it:
scp -i my-key.pem app.py ec2-user@<public-ip>:~/
ssh -i my-key.pem ec2-user@<public-ip>
pip3 install -r requirements.txt
python3 app.py

To keep it running after you disconnect, use nohup python3 app.py &, tmux, or set it up as a systemd service.

Elastic Beanstalk — for a Python web app (Flask / Django)

Best for: deploying a web application without manually provisioning EC2, load balancers, or scaling rules — Beanstalk wires them together for you.

  1. Install the CLI: pip install awsebcli
  2. In your project folder (with requirements.txt and an application.py exposing application = Flask(__name__)):
eb init -p python-3.12 my-app
eb create my-app-env
eb deploy
eb open

eb deploy zips your code, uploads it, and Beanstalk provisions EC2 + load balancer + auto scaling automatically. Push updates with eb deploy any time.

AWS CloudShell — run Python instantly, in the browser

Best for: quick scripts, testing AWS CLI commands, no installation at all.

  1. Log into the AWS Console.
  2. Click the CloudShell icon (terminal symbol) in the top navigation bar.
  3. A browser-based Linux shell launches with Python 3 and the AWS CLI pre-installed and already authenticated as you.
python3 --version
pip install boto3
python3 my_script.py

Good for scripts that talk to AWS itself (e.g. listing S3 buckets via boto3) — there's nothing to configure, credentials are automatic, but the environment resets storage limits and isn't meant for long-running processes.

Rule of thumb: occasional / event-driven → Lambda. Always-on web app → Elastic Beanstalk (or ECS/Fargate later). Need the OS, GPU, or full control → EC2. Just testing something quick → CloudShell.

09 — Connecting things together

APIs and orchestration

Lambda functions and containers rarely work alone — these two services are how you expose them and sequence them.

API layer

API Gateway

Turns a Lambda function (or any backend) into a proper HTTP/REST API — handles routing, auth, throttling, and request validation in front of your code.

Workflow

Step Functions

A visual state machine that chains Lambda calls, retries, and branching logic — e.g. "resize image → run detection model → write result to DynamoDB," with built-in error handling at each step.

Integration

EventBridge Pipes / Schedules

Connects AWS services and third-party SaaS through event rules, and runs scheduled jobs (the cloud version of cron) without a server holding the clock.

10 — Watching and locking it down

Security depth and observability

IAM controls *who* can act. These services control *what's encrypted*, *what's logged*, and *what's actively threatening* your account.

Encryption

KMS — Key Management Service

Creates and controls the encryption keys used to protect data at rest across S3, RDS, EBS, and more. You manage rotation and access, not the math.

Secrets

Secrets Manager

Stores database passwords, API keys, and tokens — your code fetches them at runtime instead of hardcoding credentials, with automatic rotation.

Audit trail

CloudTrail

Logs every API call made in your account — who did what, when, from where. The first place you look after something unexpected happens.

Threat detection

GuardDuty

Continuously analyzes account activity for malicious behavior — compromised credentials, crypto-mining, unusual API calls — using machine learning.

Edge defense

WAF & Shield

WAF filters malicious web requests (SQL injection, bad bots) at the edge. Shield protects against DDoS attacks, standard tier included free for everyone.

Tracing

X-Ray

Traces a single request as it hops across Lambda, API Gateway, and DynamoDB — showing exactly where latency or errors are introduced.

11 — Moving and querying large data

Data & analytics services

Once data outgrows a single RDS table, this is the toolkit for ingesting, transforming, and querying it at scale.

Ingest

Kinesis

Captures streaming data in real time — clickstreams, IoT sensor readings, log lines — for processing as it arrives rather than in nightly batches.

Transform

Glue

A managed ETL (extract-transform-load) service — crawls your data to infer its schema, then runs Python/Spark jobs to clean and reshape it.

Query

Athena

Runs standard SQL directly against files sitting in S3 — no database to provision, you pay per query scanned.

Warehouse

Redshift

A petabyte-scale data warehouse for heavy analytical queries and BI dashboards across structured historical data.

12 — For the AI/ML side of things

Machine learning on AWS

From training your own models to calling a ready-made API — relevant if your Python code involves computer vision, NLP, or model training.

Build & train

SageMaker

An end-to-end ML platform: managed notebooks, distributed training on GPU instances, hyperparameter tuning, and one-click model deployment to an endpoint.

Generative AI

Bedrock

Call foundation models (Claude and others) through a single API — no infrastructure to manage, pay per token/request.

Ready-made vision

Rekognition

Pre-trained computer vision API — object/face detection, OCR-style text extraction, content moderation — without training anything yourself.

Ready-made NLP

Comprehend & Transcribe

Comprehend extracts sentiment, entities, and key phrases from text. Transcribe converts speech to text — both callable straight from boto3.

Rule of thumb: need a custom model trained on your own data → SageMaker. Need a capability that already exists (read text in an image, detect a face) → the pre-trained API is faster and cheaper.

13 — Running AWS responsibly

Governance, multiple accounts, and cost control

Structure

Organizations & Control Tower

Manage many AWS accounts (dev, staging, prod) under one umbrella, with consolidated billing and guardrail policies applied automatically to every new account.

Visibility

Cost Explorer & Budgets

Cost Explorer visualizes spend by service over time. Budgets sends an alert (or triggers an action) before you blow past a spending threshold.

Discount

Savings Plans

Commit to a consistent amount of compute spend (e.g. $10/hr) for 1–3 years in exchange for up to 72% off — more flexible than Reserved Instances.

Design principles

Well-Architected Framework

AWS's own checklist for evaluating an architecture across six pillars: operational excellence, security, reliability, performance efficiency, cost optimization, and sustainability.

14 — Getting data in, and surviving disaster

Migration, hybrid cloud, and disaster recovery

Hybrid link

Direct Connect & Storage Gateway

Direct Connect is a private network line from your office/data center into AWS. Storage Gateway bridges on-prem applications to S3-backed storage transparently.

Bulk transfer

Snowball & DataSync

Snowball ships a physical encrypted device to move petabytes when your internet link is too slow. DataSync automates ongoing transfer and sync over the network.

DR strategy

Backup & restore → Multi-site active/active

Four standard tiers, increasing in cost and decreasing in recovery time: backup & restore, pilot light (core systems idling), warm standby (scaled-down copy running), and full multi-site active/active.

15 — Inside the VPC

Networking, one layer deeper

VPC was introduced as "your private network." Here's what's actually inside it.

Subnets

Public vs. private

A public subnet has a route to the internet (via an Internet Gateway) — used for load balancers. A private subnet doesn't — used for databases and app servers you don't want directly reachable.

Outbound only

NAT Gateway

Lets resources in a private subnet reach the internet (e.g. to download a pip package) without being reachable from it.

Connecting VPCs

Peering & Transit Gateway

Peering links two VPCs directly. Transit Gateway acts as a central hub when you have many VPCs (and on-prem networks) that all need to talk to each other.

Private access

VPC Endpoints / PrivateLink

Reach AWS services like S3 or DynamoDB from inside your VPC without traffic ever crossing the public internet.

16 — Beyond RDS and DynamoDB

Purpose-built databases

AWS's philosophy: pick the database built for your access pattern, instead of forcing everything into one relational database.

Relational, faster

Aurora

AWS's own MySQL/PostgreSQL-compatible engine — up to 5x the throughput of standard MySQL, with storage that auto-scales and repairs itself.

In-memory cache

ElastiCache (Redis/Memcached)

Sits in front of a database to serve hot data from memory in sub-millisecond time — cuts repeated load off RDS or DynamoDB.

Graph data

Neptune

For highly connected data — social graphs, recommendation engines, fraud detection — where the relationships matter as much as the records.

Document store

DocumentDB

MongoDB-compatible, JSON-document storage for applications already built around that data model.

17 — Decoupling, properly explained

SQS and SNS, one layer deeper

Queue

SQS — Standard

A buffer between two services. Producer drops a message in, consumer picks it up and deletes it. If the consumer is briefly down, messages just wait — nothing is lost.

Queue

SQS — FIFO

Same idea, but guarantees strict ordering and exactly-once processing — for cases like financial transactions where sequence matters.

Failure handling

Dead-Letter Queue (DLQ)

Messages that fail processing repeatedly get routed here instead of retrying forever — so you can inspect what went wrong without blocking the main queue.

Fan-out

SNS

One message published to an SNS topic can be delivered to many subscribers at once — several SQS queues, Lambda functions, and emails, simultaneously.

18 — For someone who already writes Python

App hosting shortcuts, and defining infra in Python

Container registry

ECR

Where you push Docker images so ECS, EKS, or Fargate can pull and run them — AWS's equivalent of Docker Hub, private by default.

Zero-config hosting

App Runner

Point it at a container image or a GitHub repo and it builds, deploys, and scales a web service automatically — simpler than ECS for a single service.

Full-stack frontend

Amplify

Hosts frontend apps with CI/CD from a git push, and can wire up auth, an API, and a database behind it — mainly for JS frameworks, but pairs with a Python backend.

Infra as code, in Python

AWS CDK (Python)

Define real infrastructure using Python classes instead of YAML/JSON — it synthesizes into a CloudFormation template behind the scenes.

from aws_cdk import Stack, aws_lambda as _lambda
from constructs import Construct

class MyStack(Stack):
    def __init__(self, scope: Construct, id: str, **kwargs):
        super().__init__(scope, id, **kwargs)
        _lambda.Function(self, "MyFunction",
            runtime=_lambda.Runtime.PYTHON_3_12,
            handler="lambda_function.lambda_handler",
            code=_lambda.Code.from_asset("lambda"))

Deploy it with cdk deploy — same Python you already write, describing infrastructure instead of application logic.

19 — The last mile

Backup, compliance, and edge computing

Backup

AWS Backup

One central place to schedule and manage backups across EBS, RDS, DynamoDB, EFS, and more — instead of configuring each service's backups separately.

Drift detection

AWS Config

Continuously records resource configurations and flags when something drifts from your defined compliance rules — e.g. an S3 bucket becoming public.

Edge compute

Outposts & Local Zones

Run AWS infrastructure physically inside your own data center (Outposts) or in a metro area closer to users than the nearest Region (Local Zones), for ultra-low latency.

Database migration

DMS & MGN

Database Migration Service moves a live database to AWS with minimal downtime. Application Migration Service (MGN) lifts-and-shifts entire servers as-is.

Pick a method, based on where your code is running

Function

Re-zip and update (Lambda)

Fastest loop for small functions — re-zip your code and push the new version over the old one.

zip -r function.zip .
aws lambda update-function-code \
  --function-name my-python-fn \
  --zip-file fileb://function.zip
Server

Pull latest & restart (EC2)

SSH in, pull the new code, restart the process — or automate the same steps with CodeDeploy so it happens on every push.

ssh ec2-user@<ip> '
  cd app && git pull &&
  pip3 install -r requirements.txt &&
  sudo systemctl restart myapp'
Container

Push image & redeploy (ECR → ECS/Fargate)

Build a new Docker image, push it to ECR, then tell ECS to roll your service over to it.

docker build -t my-app .
docker tag my-app:latest <acct>.dkr.ecr.<region>.amazonaws.com/my-app
docker push <acct>.dkr.ecr.<region>.amazonaws.com/my-app
aws ecs update-service --cluster my-cluster \
  --service my-app --force-new-deployment
Web app

One command (Elastic Beanstalk)

Beanstalk already knows your environment — re-deploying is a single CLI call.

eb deploy

Automating it: CI/CD, so you stop deploying by hand

Wire the pipeline above to GitHub Actions (or CodePipeline) so every git push to main redeploys automatically.

name: Deploy to Lambda
on:
  push:
    branches: [main]
jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - run: pip install -r requirements.txt -t package/
      - run: cp -r *.py package/ && cd package && zip -r ../function.zip .
      - uses: aws-actions/configure-aws-credentials@v4
        with:
          aws-access-key-id: ${{ secrets.AWS_ACCESS_KEY_ID }}
          aws-secret-access-key: ${{ secrets.AWS_SECRET_ACCESS_KEY }}
          aws-region: ap-south-1
      - run: aws lambda update-function-code --function-name my-python-fn --zip-file fileb://function.zip

From here on, "deploying" just means merging a pull request — the pipeline does the rest.
