MODULE 01
Tokenization
Before a model can learn anything, text must become numbers. Tokenization is that bridge — and its quirks explain many of GPT's surprising failures.
Concept

Why tokens, not characters?

Characters give too much granularity — a 1000-char sentence needs 1000 steps. Whole words give too little — a 500k-word vocabulary is unmanageable. Subword tokenization (BPE) is the compromise.


BPE starts with characters, then repeatedly merges the most frequent adjacent pair. "lower" → ["low","er"] because that pair appears constantly across training text.

Math

BPE merge rule

corpus = ["l o w", "l o w e r", ...]
count_pairs(corpus)
→ most_freq = ("l","o") → 8×
merge: "l"+"o" → "lo"
→ repeat until |vocab| = 50_000

1 English token ≈ 4 chars. GPT-4 vocab = 100k. Llama 3 = 128k.

Intuition

What the model actually sees

  • "Hello world" → [15496, 995]
  • "unbelievable" → ["un","believ","able"]
  • "12345" → ["1","2","3","4","5"]
  • Numbers have no numeric meaning
  • Spaces are part of tokens: " cat" ≠ "cat"
MicroGPT Connection

We'll use character-level tokenization

For our microGPT, we skip BPE entirely. Every unique character becomes a token. Tiny Shakespeare has 65 chars → vocab_size = 65. Simple, fast, and enough to learn real language patterns.

Code
# character tokenizer (our microGPT) chars = sorted(set(text)) vocab_size = len(chars) # 65 stoi = {ch:i for i,ch in enumerate(chars)} itos = {i:ch for i,ch in enumerate(chars)} encode = lambda s: [stoi[c] for c in s] decode = lambda l: ''.join([itos[i] for i in l]) data = torch.tensor(encode(text))
PYTHON
Why it works

Characters still capture patterns

Even at the character level, the model must learn: spelling, grammar, word boundaries, names, syntax. It's a harder task but proves the architecture works. Add BPE later for efficiency.

2024 RESEARCH

Llama 3 uses 128k vocab (vs GPT-2's 50k) for better multilingual coverage. MegaByte (2024) processes raw bytes — no tokenizer at all — but needs much more compute. Tokenization bugs cause ~15% of arithmetic errors: "9.11 > 9.9" fails because "9",".",1","1" and "9",".","9" are compared token-by-token, not numerically.

MODULE 02
Embeddings
Token IDs are integers — you can't differentiate through them. Embeddings convert each integer into a continuous vector that can be learned and compared geometrically.
Concept

A lookup table of meaning

The embedding table E has shape (vocab_size × n_embd). Token ID 42 fetches row 42 — a vector of n_embd floats. This vector is the model's learned representation of that token.


Similar tokens end up nearby because they appear in similar contexts during training. This is the distributional hypothesis: meaning comes from usage patterns.

Math

Embedding lookup

E ∈ ℝ^(V × d)
token_id = 42
x = E[42] # row lookup, O(1)

# dot product = similarity
sim(a,b) = a·b / (|a|·|b|)
sim ∈ [-1, +1]
Geometry

Vector arithmetic works

  • king − man + woman ≈ queen
  • Paris − France + Italy ≈ Rome
  • These emerge from training, not design
  • 768 dims in GPT-2, 4096 in Llama 3
30°
-20°

Position Encoding

Word order matters

Attention is order-blind — "cat sat" and "sat cat" look identical. We add a second embedding for position. Now the model has both "what this token is" and "where it sits."

Parameters

Embedding table size

For our microGPT: 65 × 64 = 4,160 params. For GPT-2: 50,257 × 768 = 38.6M params — nearly all in embeddings alone. This is why vocab size is a key architectural choice.

MODULE 03
Self-Attention
The mechanism that lets every token look at every other token and decide how much to weight their information. This is why transformers understand context.
Concept

Query, Key, Value

Every token projects itself into three roles. Query: "what am I looking for?" Key: "what do I advertise?" Value: "what do I give if selected?"


Token A's query dots against every Key. High score = strong match. Softmax normalizes to probabilities. Output = weighted sum of Values.

Math
Q = x·Wq, K = x·Wk, V = x·Wv

scores = Q·Kᵀ / √dₖ
scores = mask(scores) # causal
weights = softmax(scores)
out = weights · V

Divide by √dₖ prevents saturation at large dims. Mask future tokens with −∞.

Intuition

What each part does

  • Q·Kᵀ: how much do I match you?
  • ÷√dₖ: keeps gradients healthy
  • mask: GPT can't see the future
  • softmax: weights sum to 1
  • ·V: take a mix of everyone's info
MicroGPT Code
class Head(nn.Module): def __init__(self, head_size): self.q = nn.Linear(n_embd, head_size, bias=False) self.k = nn.Linear(n_embd, head_size, bias=False) self.v = nn.Linear(n_embd, head_size, bias=False) # causal mask — upper triangle = -inf self.register_buffer('mask', torch.tril(torch.ones(T, T))) def forward(self, x): q, k, v = self.q(x), self.k(x), self.v(x) sc = q @ k.transpose(-2,-1) * k.shape[-1]**-0.5 sc = sc.masked_fill(self.mask==0, float('-inf')) w = F.softmax(sc, dim=-1) return w @ v
PYTHON
Multi-Head

Run attention in parallel

Multiple heads each compute attention independently with different Wq, Wk, Wv. One head might learn syntax, another semantics. Outputs concatenated and projected back.

Our microGPT: 4 heads × 16 dim = 64-dim total.

Why it works

Context flows through attention

Before attention: each token only knows itself. After attention: each token carries a weighted mixture of all past tokens. This is how "bank" knows it means "river bank" vs "financial bank" from context.

MODULE 04
Transformer Block
Attention + FFN + residuals + layer norm. One block refines the token representations slightly. Stack 12 blocks → GPT-2. Stack 96 → GPT-3. Each block adds a tiny delta to the "residual stream."
Concept

The residual stream

Every sublayer uses x = x + sublayer(x). The original signal is never destroyed — only enriched. This lets gradients flow backward through 96 layers without vanishing.


Think of it as each layer "writing suggestions" to a shared whiteboard. The whiteboard accumulates all suggestions but keeps the original.

Math
x = x + Attention(LayerNorm(x))
x = x + FFN(LayerNorm(x))

FFN(x) = W₂ · GELU(W₁·x + b₁) + b₂
W₁: d → 4d, W₂: 4d → d

LayerNorm: (x−μ)/σ · γ + β
Roles

What each piece does

  • Attention: mix info across tokens
  • FFN: process each token alone (memory)
  • LayerNorm: stabilize activations
  • Residual: prevent vanishing gradients
  • Stack N blocks: N chances to refine
MicroGPT Code
class Block(nn.Module): def __init__(self, n_embd, n_head): self.attn = MultiHeadAttention(n_head, n_embd//n_head) self.ffn = FFN(n_embd) self.ln1 = nn.LayerNorm(n_embd) self.ln2 = nn.LayerNorm(n_embd) def forward(self, x): # pre-norm + residual (modern GPT style) x = x + self.attn(self.ln1(x)) x = x + self.ffn(self.ln2(x)) return x
PYTHON
FFN as Memory

Where facts are stored

Research (Geva et al. 2021) proved FFN layers are key-value memories. Specific neurons fire for specific patterns — "capital of France" activates neurons that output "Paris." Fine-tuning edits these neurons.

Forward Pass
Trace a single token from raw integer to predicted probability distribution. This is inference — what runs when ChatGPT replies to you.
Complete Forward Pass Code
def forward(self, idx, targets=None): B, T = idx.shape # 1. embed tokens + positions tok = self.tok_emb(idx) # (B,T,C) pos = self.pos_emb(torch.arange(T)) x = tok + pos # (B,T,C) # 2. run through all blocks for block in self.blocks: x = block(x) # (B,T,C) # 3. final layer norm x = self.ln_f(x) # (B,T,C) # 4. project to vocab logits = self.lm_head(x) # (B,T,V) # 5. loss if training if targets is not None: loss = F.cross_entropy( logits.view(-1,V), targets.view(-1)) return logits, loss

Always know your tensor shape

idx: (B, T) integers
after embed: (B, T, C) floats
after blocks: (B, T, C) floats
logits: (B, T, V) raw scores
probs: (B, T, V) sums to 1

B=batch, T=time, C=channels, V=vocab

MODULE 06
Backpropagation
How the model learns. Compute how wrong the prediction was (loss), then use the chain rule to compute how much each weight contributed to that wrongness. Nudge them all in the right direction.
Concept

Chain rule over the compute graph

Every operation in the forward pass is recorded. Backward pass replays them in reverse, multiplying local gradients (chain rule). PyTorch does this automatically via autograd.


Residual connections guarantee gradient highway — gradients flow directly to early layers without being multiplied through many weight matrices.

Math
L = CrossEntropy(logits, targets)

∂L/∂logits = p̂ − y
(prediction minus one-hot truth)

∂L/∂W = ∂L/∂out · ∂out/∂W
(chain rule, layer by layer)

W ← W − lr · ∂L/∂W
Gradient at output

The error signal

If model predicted "e" with prob 0.02 but correct answer was "e" (prob should be 1.0), gradient = 0.02 − 1.0 = −0.98. This large negative gradient pushes the weight to increase "e"'s probability next time.

MicroGPT Code

PYTHON
AdamW optimizer

Smarter than plain SGD

AdamW tracks a running average of gradients (momentum) and squared gradients (adaptive learning rate). Parameters that always get large gradients → smaller effective lr. Rare parameters → larger lr. Weight decay prevents overfitting.

Gradient clipping

Preventing explosions

# add this before optimizer.step() torch.nn.utils.clip_grad_norm_( model.parameters(), max_norm=1.0 # clip if |grad|>1 )
PYTHON

If gradient norm > 1.0, scale all gradients down proportionally. Prevents loss spikes from bad batches.

Hyperparameters
The dials you set before training. They define the model's size, memory, and speed — and they interact with each other in non-obvious ways.
▸ CONCEPT

batch_size = 32
Process 32 independent sequences in parallel. Bigger batches use more GPU memory but give more stable gradient estimates — noise averages out across examples.

▸ MATH

Memory scales linearly with batch. Each sequence costs block_size × n_embd × 4 bytes (float32). 32 × 128 × 64 × 4 = 1 MB just for the input tensor — tiny by modern standards.

memory ≈ batch × T × d × 4 bytes

02
Data Pipeline
Character-level tokenization + sliding window batching. From raw text to (input, target) tensor pairs the model can learn from.
▸ TOKENIZER

Character-level BPE — each unique character is a token. Shakespeare has 65 unique chars → vocab_size=65. Simple, but powerful enough to learn real patterns. GPT-4 uses ~100k tokens.

▸ SLIDING WINDOW

From one window of 128 chars we get 128 training signals. Position 0 predicts char 1, position 1 predicts char 2, etc. This is why language models are so data-efficient.

x = text[i : i+T] y = text[i+1 : i+T+1]
▸ SPLIT

90% training / 10% validation. Validation data is never trained on — it measures how well the model generalises, not just memorises. With 1M chars: ~900k train, ~100k val.

PYTHON with open('input.txt') as f: text = f.read() chars = sorted(set(text)) # e.g. ['\n',' ','!','&',...,'z'] — 65 chars vocab_size = len(chars) # 65 stoi = {c:i for i,c in enumerate(chars)} encode = lambda s: [stoi[c] for c in s] # "Hi" → [35, 46] decode = lambda l: ''.join([chars[i] for i in l]) data = torch.tensor(encode(text), dtype=torch.long) # shape (1M,) n = int(0.9*len(data)) train_data, val_data = data[:n], data[n:] def get_batch(split): d = train_data if split=='train' else val_data ix = torch.randint(len(d)-block_size, (batch_size,)) # 32 random starts x = torch.stack([d[i:i+block_size] for i in ix]) # (32, 128) y = torch.stack([d[i+1:i+block_size+1] for i in ix]) # (32, 128) — shifted by 1 return x.to(device), y.to(device)
03
Attention Head
The fundamental operation of every transformer. Each token asks a query, every other token offers a key, and the dot-products decide who gets listened to.
▸ Q, K, V

Query — "what am I looking for?" Key — "what do I contain?" Value — "what do I pass along if attended to?" Three separate learned linear projections from the same input.

▸ SCALED DOT-PRODUCT
score(Q,K) = Q·Kᵀ / √dₖ

Without √dₖ scaling, large embedding dims push dot products into regions where softmax gradients vanish. √16 = 4 keeps scores in a stable range.

▸ CAUSAL MASK

The lower-triangular mask sets all future positions to −∞ before softmax → they become exactly 0 after softmax. This enforces left-to-right generation — position 5 cannot see positions 6, 7, …

PYTHON class Head(nn.Module): def __init__(self, hs): # hs = head_size = n_embd // n_head = 16 super().__init__() self.q = nn.Linear(n_embd, hs, bias=False) # (64→16) "what I want" self.k = nn.Linear(n_embd, hs, bias=False) # (64→16) "what I have" self.v = nn.Linear(n_embd, hs, bias=False) # (64→16) "what I give" self.register_buffer('mask', torch.tril(torch.ones(block_size, block_size))) self.drop = nn.Dropout(dropout) def forward(self, x): # x: (B, T, 64) B,T,C = x.shape q,k,v = self.q(x), self.k(x), self.v(x) # each (B,T,16) sc = q @ k.transpose(-2,-1) * k.shape[-1]**-0.5 # (B,T,T) scores sc = sc.masked_fill(self.mask[:T,:T]==0, float('-inf')) w = self.drop(F.softmax(sc, dim=-1)) # (B,T,T) weights, sum=1 return w @ v # (B,T,16)
04
Multi-Head Attention
Run 4 independent attention heads in parallel, each looking for different patterns. Concatenate, then project back to the model dimension.
▸ WHY MULTIPLE HEADS?

One head is limited to one "type" of relationship. Multiple heads let the model simultaneously track syntax, co-reference, semantics, and other patterns — different heads specialize during training.

▸ DIMENSIONS
head_size = n_embd / n_head = 64 / 4 = 16

4 heads × 16 dim = 64 total. After concatenation, a final linear layer mixes information across heads before passing to the FFN.

▸ PROJECTION

The proj layer (64→64) is critical — without it, heads are just concatenated with no interaction. It lets the model learn which combinations of head outputs are most useful.

PYTHON class MultiHead(nn.Module): def __init__(self, n_head, hs): super().__init__() self.heads = nn.ModuleList([Head(hs) for _ in range(n_head)]) # 4 heads self.proj = nn.Linear(n_head*hs, n_embd) # 64→64 mix across heads self.drop = nn.Dropout(dropout) def forward(self, x): # run all heads, each gives (B,T,16), cat → (B,T,64) out = torch.cat([h(x) for h in self.heads], dim=-1) return self.drop(self.proj(out)) # → (B,T,64)
05
Feed-Forward Network
After attention mixes information across tokens, the FFN processes each token independently. Expand → activate → contract. This is where most computation happens.
▸ 4× EXPANSION

Expand from 64 → 256 dims before contracting back. This expansion is a standard GPT design choice — the "thinking room". Most of the model's parameters live here: 2 × (64×256) = 32,768 params per FFN.

▸ GELU ACTIVATION
GELU(x) = x · Φ(x)

Smoother than ReLU — allows small negative values through. Φ(x) is the Gaussian CDF. In practice: slightly better loss than ReLU for transformers, at no extra cost.

▸ NO CROSS-TOKEN MIXING

Unlike attention, the FFN operates position-independently — each token's 64-dim vector is transformed in isolation. You can think of it as: attention = routing, FFN = computation.

PYTHON class FFN(nn.Module): def __init__(self): super().__init__() self.net = nn.Sequential( nn.Linear(n_embd, 4*n_embd), # 64 → 256 (expand) nn.GELU(), # smooth nonlinearity nn.Linear(4*n_embd, n_embd), # 256 → 64 (contract) nn.Dropout(dropout)) def forward(self, x): return self.net(x) # (B,T,64)→(B,T,64), token-wise
06
Transformer Block
Attention + FFN, each wrapped in a residual connection and a LayerNorm. Stack 4 of these and you have the full transformer body.
▸ RESIDUAL CONNECTION
x = x + Attention(LN(x)) x = x + FFN(LN(x))

The x + part creates a gradient highway. Gradients flow back through the addition without transformation, making deep networks trainable. Without residuals, 4+ layer networks fail to learn.

▸ PRE-LN vs POST-LN

This code uses Pre-LN (LayerNorm before each sub-layer) — more stable training than the original "Post-LN" from Attention Is All You Need. GPT-2 also uses Pre-LN. Helps at the start of training when activations are noisy.

▸ LAYER NORM

Normalizes each token's 64-dim vector to mean≈0, std≈1, then applies learned scale (γ) and shift (β). Only 2×64=128 parameters per LN, but crucial for gradient stability in deep stacks.

LN(x) = γ · (x−μ)/σ + β
PYTHON class Block(nn.Module): def __init__(self): super().__init__() hs = n_embd // n_head # 16 self.attn = MultiHead(n_head, hs) self.ffn = FFN() self.ln1 = nn.LayerNorm(n_embd) self.ln2 = nn.LayerNorm(n_embd) def forward(self, x): # x: (B, T, 64) x = x + self.attn(self.ln1(x)) # residual + attention x = x + self.ffn(self.ln2(x)) # residual + FFN return x # still (B, T, 64)

▸ EMBEDDINGS

tok_emb: 65×64 lookup table. Each of the 65 chars has a learned 64-dim vector.
pos_emb: 128×64 lookup table. Each position 0–127 has a learned vector. Both are added together — "what I am" + "where I am".

PYTHON class MicroGPT(nn.Module): def __init__(self): super().__init__() self.tok_emb = nn.Embedding(vocab_size, n_embd) # 65×64 self.pos_emb = nn.Embedding(block_size, n_embd) # 128×64 self.blocks = nn.Sequential(*[Block() for _ in range(n_layer)]) self.ln_f = nn.LayerNorm(n_embd) self.lm_head = nn.Linear(n_embd, vocab_size, bias=False) # 64→65 def forward(self, idx, targets=None): B, T = idx.shape x = self.tok_emb(idx) + self.pos_emb(torch.arange(T, device=device)) x = self.ln_f(self.blocks(x)) # (B,T,64) through 4 blocks logits = self.lm_head(x) # (B,T,65) loss = None if targets is not None: loss = F.cross_entropy(logits.view(-1, vocab_size), targets.view(-1)) return logits, loss
08
Training Loop
Forward → loss → zero_grad → backward → step. Five lines repeated 5000 times. Each iteration nudges 200k parameters slightly closer to predicting Shakespeare.
▸ CROSS-ENTROPY LOSS
L = -log P(correct token)

For random weights over 65 chars: L = log(65) ≈ 4.17. After training: L ≈ 1.5–1.8. The loss measures surprise — how unlikely did the model find the correct next character?

▸ ADAMW

Adam with weight decay. Maintains per-parameter momentum (m) and variance (v) estimates. Adapts step size per parameter — common weights get smaller updates. Weight decay penalizes large weights for better generalization.

θ = θ − lr · m̂/(√v̂ + ε) − wd·θ
▸ BACKPROP ORDER

Critical: zero_grad → backward → step. Never swap. zero_grad(set_to_none=True) frees gradient memory rather than zeroing (faster). backward() fills .grad for every parameter. step() uses those grads to update weights.

PYTHON model = MicroGPT().to(device) opt = torch.optim.AdamW(model.parameters(), lr=lr) print(f"params: {sum(p.numel() for p in model.parameters())/1e3:.1f}k") for step in range(max_steps): xb, yb = get_batch('train') # (32,128), (32,128) _, loss = model(xb, yb) # forward pass + loss opt.zero_grad(set_to_none=True) # clear old gradients loss.backward() # compute ∂loss/∂θ for all θ opt.step() # θ = θ − lr·grad if step % eval_every == 0: print(f"step {step}: loss={loss.item():.4f}")
EXPECTED LOSS CURVE

Step 0: ~4.1 (random) → Step 500: ~2.5 → Step 2000: ~1.9 → Step 5000: ~1.6. Each halving of loss = the model becoming roughly 2× more certain about the next character.

Generation
Autoregressive sampling — one token at a time. The model sees its own output, feeds it back in as input, and grows the sequence until done.
▸ AUTOREGRESSIVE

Each generated token is appended to the input for the next step. The model conditions on its own outputs — errors can compound. This is the fundamental architecture of GPT, LLaMA, etc.

▸ SAMPLING vs GREEDY

multinomial sampling — draw from the distribution. Produces variety and creativity. argmax — always pick the most likely token. Deterministic but often repetitive. Temperature controls the tradeoff.

probs = softmax(logits / T) # T<1 → sharper, T>1 → flatter
▸ CONTEXT WINDOW CROP

idx[:, -block_size:] — once the sequence exceeds 128 tokens, crop to the last 128. The model literally cannot see beyond its context window. This is why longer context windows matter so much for real applications.

concept 01
Tokenization & BPE
How text becomes integers — the very first transformation. Every word, punctuation mark, and space gets mapped to a number before the model sees anything.
WHY

Models can't process raw text. Tokenization creates a fixed vocabulary so the embedding table has a finite size. BPE balances word-level meaning with subword flexibility for unknown words.

HOW

BPE starts with characters, then iteratively merges the most frequent pair. "low" + "er" → "lower" if that pair appears often. Stops at target vocab size (50k–100k).

WHEN IT FAILS

Numbers are split oddly ("100000" → ["100","000"]). Non-English languages get fragmented. Code tokenization is inefficient. Adversarial spacing breaks recognition.

2024 Research

Tokenizer-free models (MegaByte, 2024) process raw bytes instead of tokens, eliminating BPE's biases. Llama 3 uses a 128k vocab (vs GPT-4's ~100k) for better multilingual coverage. TikToken (used in GPT-4) is 3–5× faster than HuggingFace tokenizers. Research shows tokenization artifacts cause ~15% of arithmetic errors in LLMs — the model sees "1" + "2" as separate tokens with no inherent numeric relationship.

concept 02
Embedding Space Geometry
Each token lives as a point in 768+ dimensional space. The geometry of that space encodes meaning, and understanding it reveals how LLMs "think."
WHY

Discrete IDs can't be differentiated — you can't take a gradient w.r.t. integer 3797. Continuous vectors enable backprop and encode semantic relationships as geometric distance.

HOW

Embedding matrix E ∈ ℝ^(V×d). Each row is a learned vector. Similar words end up nearby because they appear in similar contexts during training (distributional hypothesis).

WHEN

Embeddings become useful after ~1B training tokens. Before that, the geometry is random. Rare words stay poorly trained even in large models (long-tail problem).

royalty
2024 Research

Isotropy problem: Embeddings cluster in a narrow cone (not spread uniformly), causing "representation degeneration." LASER (2023) removes top singular vectors and improves performance. Matryoshka Representation Learning (MRL, 2022–2024) trains embeddings that work at multiple dimensions simultaneously — you can use 64, 128, or 768 dims of the same vector. Used in OpenAI's text-embedding-3 models.

concept 03
Positional Encoding
Attention is permutation-invariant — it doesn't know if "cat sat" or "sat cat." Position encodings inject order. Three generations of approaches: sinusoidal → learned → RoPE.
WHY

Self-attention computes all pairwise interactions simultaneously. Without position info, the model is a "bag of tokens" — word order is invisible. Position encodings break symmetry.

HOW

Original: PE(pos,2i) = sin(pos/10000^(2i/d)). RoPE: rotate Q and K vectors by position-dependent angles so dot products naturally encode relative distance.

WHEN

Sinusoidal fails to generalize beyond training length. RoPE (used in Llama, GPT-NeoX) generalizes better. YaRN extends context to 128k+ tokens via NTK interpolation.

2024 Research

RoPE (Su et al., 2021) is now the dominant approach — used in Llama 2/3, Mistral, Gemma, Falcon. ALiBi (2022) adds a linear bias to attention scores based on distance — no positional vectors needed. YaRN (2023) extends Llama's 4k context to 128k by interpolating RoPE frequencies. LongRoPE (2024, Microsoft) extends to 2 million tokens using non-uniform interpolation.

concept 04
Attention Mechanism — Deep Dive
The core operation of every transformer. Why the √dₖ scaling matters, what causal masking does, and how FlashAttention makes it 10× faster.
WHY SCALE BY √dₖ?

For large dₖ, dot products grow in magnitude. Large values push softmax into saturation (near-0 gradients). Dividing by √dₖ keeps variance ~1 regardless of dimension.

HOW CAUSAL MASKING

During training, the model sees the full sequence but masks future tokens with −∞ before softmax. Those positions become 0 after softmax, so they contribute nothing to the output.

WHEN HEADS SPECIALIZE

Early layers: syntactic (subject-verb). Middle layers: semantic (coreference). Late layers: task-specific (prediction). Heads emerge spontaneously — they're never explicitly programmed.

64
2024 Research

FlashAttention-3 (2024) rewrites attention using hardware-aware tiling on H100 GPUs — 2× faster than FA2, near-theoretical-peak FLOP utilization. GQA (Grouped Query Attention) used in Llama 3 and Mistral — multiple query heads share one key/value head, reducing KV cache memory by 8×. Sparse Attention (Longformer, BigBird) attends to local windows + global tokens for O(n) instead of O(n²) complexity. Differential Attention (2024, Microsoft) subtracts two softmax attention maps to cancel noise — reduces hallucination.

concept 05
FFN as Factual Memory
The feed-forward network is not just a non-linearity. Research shows it acts as a key-value memory store — each neuron encodes a specific fact or pattern.
WHY 4× EXPANSION?

Empirically found to be optimal for the compute budget. The wide hidden layer allows the network to store more "memories." Too narrow → underfitting. Too wide → inefficient compute.

HOW IT STORES FACTS

W₁ rows act as "keys" matching input patterns. W₂ columns act as "values" retrieved when a key fires. "The capital of France is ___" fires specific neurons that retrieve "Paris."

MoE: CONDITIONAL COMPUTE

Mixture of Experts (Mistral, GPT-4 rumored) has N FFN experts but only activates 2 per token. Same quality, 4× fewer FLOPs per forward pass. Scale params without scaling compute.

2024 Research

Geva et al. (2021, 2023) proved FFN layers are key-value memories — specific neurons encode specific facts. Mixtral 8×7B (2024, Mistral) uses 8 experts per layer, routes 2 per token — 46B total params but only 12B active. Matches GPT-3.5 quality. DeepSeek-V2 (2024) uses 160 experts with MLA (Multi-head Latent Attention) — most parameter-efficient model to date. GELU vs SwiGLU: Llama uses SwiGLU (Gated Linear Unit) which outperforms GELU by ~1 ppl on language modeling.

concept 06
Training Dynamics & Loss Landscape
What actually happens during training — loss spikes, grokking, double descent, and why the learning rate schedule matters more than most people think.
WHY WARMUP?

At step 0, weights are random and gradients are huge. A high LR causes immediate divergence. Warmup slowly increases LR over ~2000 steps until gradients stabilize.

HOW LOSS SPIKES HAPPEN

Large batches, bad data (duplicates, low quality), or too-high LR cause sudden loss jumps. Solution: gradient clipping (max norm=1.0) and data filtering upstream.

GROKKING

Model first memorizes training data (overfits), then suddenly "generalizes" after much more training — sometimes 10× longer. This delayed generalization is called grokking.

Grokking (Power et al., 2022) — delayed generalization discovered in small transformers on modular arithmetic. Extended to large LLMs in 2024. Loss spikes in GPT-4 training caused by data quality issues — solved by deduplication and quality filters. concept 07
Scaling Laws & Chinchilla
How loss scales predictably with compute, data, and parameters. The Chinchilla result upended GPT-3's training recipe and reshaped how every model is trained today.
WHY SCALING LAWS?

If loss is a power law of compute, you can predict model quality before training. This makes billion-dollar training decisions tractable — run small experiments, extrapolate.

CHINCHILLA RESULT

Optimal: N params ∝ D tokens (1:20 ratio). GPT-3 (175B params, 300B tokens) was undertrained. Chinchilla (70B params, 1.4T tokens) matched GPT-3 quality at 4× less compute.

WHEN LAWS BREAK

Laws hold for next-token prediction loss. They don't predict emergent capabilities (e.g., chain-of-thought appears abruptly at ~100B params). "Emergence" may be a measurement artifact.

2024 Research

Chinchilla (Hoffmann et al., 2022, DeepMind) — optimal: 20 tokens per parameter. Llama 3 (2024, Meta) trained 8B on 15T tokens (1875 tokens/param) — far beyond Chinchilla optimal, showing inference-time compute matters. Scaling laws for reasoning (2024): OpenAI o1 shows test-time compute scaling as a new axis. MFU (Model FLOP Utilization): A100 achieves ~35–50% MFU in practice. Key bottleneck is memory bandwidth, not compute.

concept 08
Inference, KV Cache & Quantization
Training is done once. Inference runs billions of times. Every trick here — KV caching, speculative decoding, quantization — is about making the forward pass faster and cheaper.
WHY KV CACHE?

Without caching, generating token 100 recomputes attention for all 100 previous tokens. With KV cache, only the new token needs computation. O(n²) → O(n) per step.

SPECULATIVE DECODING

A small "draft" model (e.g., 7B) generates 5 tokens speculatively. The large model (70B) verifies all 5 in one forward pass. If accepted, 5× throughput for free.

QUANTIZATION TRADEOFFS

FP32 (4 bytes) → FP16 (2 bytes) → INT8 (1 byte) → INT4 (0.5 bytes). Quality drops ~0% at FP16, ~1% at INT8, ~3–8% at INT4. GGUF/llama.cpp enables 70B on M2 Mac.

2024 Research

FlashAttention-3 (2024) — H100-optimized, ~740 TFLOP/s (75% MFU). Speculative decoding (2023, Google/DeepMind) now production in Gemini. GPTQ / AWQ / GGUF (2023–2024) — weight-only quantization to INT4 with minimal quality loss. Continuous batching (vLLM, 2023) — dynamic request scheduling, 23× throughput vs naive batching. PagedAttention (2023) — KV cache memory managed like OS virtual memory, eliminating 60–80% of memory waste.

concept 09
RLHF, DPO & Alignment
A pretrained LLM is a next-token predictor. To make it helpful, harmless, and honest requires a second training phase — aligning its outputs with human preferences.
WHY RLHF?

Pretraining on internet text gives capability but also harmful patterns. RLHF fine-tunes the model to maximize human approval scores — making it follow instructions and avoid harmful outputs.

HOW RLHF WORKS

1. Supervised fine-tuning on demonstrations. 2. Train reward model on human preference pairs. 3. PPO reinforcement learning — use reward model as the "environment" to optimize the policy.

DPO: RLHF WITHOUT RL

Direct Preference Optimization (2023) achieves same alignment without RL. Directly optimizes a classification loss on (chosen, rejected) pairs. 10× simpler, equally effective.

2024 Research

DPO (Rafailov et al., 2023) — now used in Llama 3, Mistral, Gemma. Simpler than PPO and comparable quality. RLAIF (2024, Google) — replace human raters with Claude/GPT-4. Scales to millions of preference pairs. Constitutional AI (Anthropic, 2022–2024) — model critiques its own outputs using a "constitution" of principles. Used in Claude. Reward hacking: models find ways to maximize reward without being genuinely helpful — active research area. ORPO (2024): odds-ratio preference optimization, merges SFT + alignment in one pass.

Multiply local gradients

TEMPERATURE

Sharpness of distribution

logits_scaled = logits / T. T→0: argmax (always pick highest prob). T=1: sample as-is. T→∞: uniform random. For creative text: 0.8–1.2. For code: 0.2–0.5. For factual QA: 0.0–0.3.

WHY SOFTMAX

Differentiable argmax

argmax picks one winner — gradient is zero everywhere else, training stops. softmax spreads probability smoothly, giving nonzero gradients to all logits. Gradient of loss flows back to every input score.

TEMPERATURE

Controls information density

Low T → peaky distribution → attends to 1 token → sharp focus. High T → flat distribution → attends to all tokens equally → no context. Training uses T=1. Creative generation uses T=0.7–1.2.

NUMERICAL STABILITY

Subtract max before exp

exp(1000) overflows float32. The trick: subtract max before computing. softmax(x) = softmax(x−max(x)) mathematically identical but never overflows. This is in every transformer implementation.

ALGORITHM

Frequency-driven merges

1. Start with all characters as tokens. 2. Count all adjacent pairs across full corpus. 3. Merge most-frequent pair into one token. 4. Recount. 5. Repeat until vocab_size. Each merge reduces total tokens by ~corpus_freq of that pair.

ENTROPY

Uncertainty = information

Cross-entropy loss = average bits needed to encode the true token given the model's distribution. Random model: log₂(vocab_size) ≈ 16 bits. Good GPT-2: ~4 bits. Each layer reduces entropy as the model narrows its prediction.

What does each layer know?

exp(cross-entropy)

THE IO BOTTLENECK

Bandwidth, not FLOPs

A100 GPU: 312 TFLOP/s compute but only 2 TB/s HBM bandwidth. For N=1024, writing the N×N attention matrix = 1M floats × 4 bytes = 4MB to HBM — at 2TB/s that's 2μs. Done N times per layer = 2ms per layer just in memory writes. FlashAttention eliminates this.

CHARACTER COUNTING

"How many R's in strawberry?"

"strawberry" → ["straw","berry"]. The model never sees individual characters — only subword tokens. It must reconstruct character-level information from subword representations. Correct answer (3 R's) requires attending to internal token structure which isn't explicitly encoded.

DECIMAL COMPARISON

9.11 > 9.9 confuses LLMs

"9.11" → ["9",".","11"] and "9.9" → ["9",".","9"]. The model compares [9,.,"11"] vs [9,.,"9"] token-by-token. 11 > 9 as integers → model says 9.11 > 9.9. The decimal point's semantic meaning is lost in tokenization. No numeric understanding exists — only pattern matching.

STRING REVERSAL

Can't reverse "hello"

"hello" is 1 token. To reverse it, the model would need to attend to internal character positions within the token — which aren't individually represented. Works for character-level models. Breaks for BPE models where words are atomic. Solution: add spaces between letters before asking.

HOW AUTOGRAD WORKS

Every op records its backward fn

When you write y = x * w + b in PyTorch with requires_grad=True, it creates a computation graph node storing: the output value, pointers to inputs, and the local gradient function. .backward() traverses this graph in topological order, multiplying local gradients (chain rule).

Simulate large batches cheaply

Every model goes through 4 phases

PROBING (ALAIN & BENGIO 2017)

Linear readout from hidden states

Train a logistic regression on frozen hidden states to predict a linguistic property. High accuracy = the model encodes that property. Low accuracy = it doesn't. If only deep layers have it, the model learns it top-down. If early layers have it, it's input-driven.

WHAT PROBES FIND

Layer-by-layer knowledge

Layers 1–4: POS tags, morphology (surface features). Layers 5–8: syntactic dependencies, coreference (structural). Layers 9–12: semantic roles, entity types, world knowledge (conceptual). This hierarchy appears across BERT, GPT-2, and Llama.

PROBING VS PATCHING

Correlation is not causation

A probe showing a layer "knows" something doesn't mean that layer uses it. Activation patching (swap activations between runs) shows whether the information is causally used. Both methods together give mechanistic understanding.

LORA (HU ET AL. 2021)

ΔW = BA where B∈ℝ^(d×r), A∈ℝ^(r×k)

Original weight W₀ is frozen. Two new matrices added: A initialized from N(0,σ²), B initialized to 0 (so ΔW=0 at start). During forward: h = W₀x + (α/r)·BAx. Only A and B are trained. For d=1024, r=4: 8192 params vs 1,048,576 — 128× reduction.

The update ΔW lies in a low-rank subspace — most fine-tuning changes are low-dimensional. r=1: very cheap, loses some quality. r=4: 80% of full fine-tuning quality. r=16: 95%+. r=64: nearly identical. Higher r = more params = higher quality ceiling.

Quantize the frozen W₀ to INT4 (NF4 format). Keep LoRA adapters in FP16. Fine-tune 70B on a single 48GB GPU. Quality matches FP16 full fine-tuning. Memory: 35GB (INT4 base) + 0.5GB (LoRA) vs 140GB for FP16 full. The most widely used fine-tuning method in 2024.

DISCOVERY (XIAO ET AL. 2023)

Sink tokens absorb attention

In every layer of GPT-2, LLaMA, and all major LLMs, the first token receives disproportionately large attention weight — often 30–80% of total. This is true regardless of what the first token is: "The", a BOS token, or even a period.

Softmax must sum to 1

When no token is "relevant," softmax still must produce probabilities summing to 1. Rather than distributing evenly (losing sharpness), models learn to dump excess probability mass on the first token as a "garbage collector." First token acts as a null attender.

Infinite context with sink tokens

Parameter Efficiency
Weight Tying
The embedding matrix and the unembedding matrix are the same weights — shared, transposed. This saves 38M parameters in GPT-2 alone. It also forces the model to learn representations that are both good at encoding input tokens and predicting output tokens simultaneously.
WEIGHT TYING · EMBEDDING / UNEMBEDDING · PARAMETER SHARING
WEIGHT TYING (PRESS & WOLF 2017)

W_embed = W_unembed^T

The input embedding E ∈ ℝ^(V×d) and output projection W_u ∈ ℝ^(d×V) share parameters: W_u = E^T. Forward: token → E[token_id]. Output: x_final · E^T → logits. Same matrix, two transposes of each other.

WHY IT WORKS

Same representation for in and out

The model learns that token 42 ("cat") should produce an embedding close to the direction that the output layer uses to predict "cat." This geometric consistency improves quality — and saves V×d parameters. GPT-2 saves 50,257×768=38.6M params.

EXCEPTIONS

When not to tie

Encoder-decoder models (T5, BART) sometimes don't tie: encoder vocab ≠ decoder vocab. Very large vocabulary models may untie for quality. Models trained with very different tokenizer for input vs output. Most decoder-only models (GPT, Llama) use tying.

BEAM SEARCH

TASK ARITHMETIC (2023)

ΔW = W_finetuned − W_base

Ilharco et al.: fine-tuning creates a "task vector" ΔW in weight space. Add task vectors from multiple models: W_merged = W_base + α₁ΔW₁ + α₂ΔW₂. The merged model has both capabilities. Subtract a task vector to remove a capability. Works surprisingly well.

CATASTROPHIC FORGETTING

Fine-tuning overwrites pretraining

Neural networks store knowledge in overlapping weight distributions. Task B fine-tuning shifts weights to minimize B's loss — but these same weights also encode Task A knowledge. No mechanism prevents the overwriting. Full fine-tuning of GPT-2 on code → forgets 40-80% of language ability in 1000 steps.

EWC (KIRKPATRICK ET AL. 2017)

Elastic Weight Consolidation

Identify which weights are "important" for Task A using Fisher information matrix. Add a penalty term: λ·Σ F_i·(θ_i - θ*_i)² that resists changing important weights. Parameters important for Task A are "elastic" — they can move but with resistance. Reduces forgetting 2-5× with minimal Task B degradation.

REPLAY BUFFERS

Remember by practicing

Store a small buffer of Task A examples (or generate synthetic ones). During Task B training, interleave Task A examples. Loss = L_B + λ·L_A_replay. Simple and effective — biological analogy: hippocampal replay during sleep consolidates memories. LoRA: freeze base weights entirely, only train adapters.

HOW PROMPT CACHING WORKS

Reuse the KV cache, not just text

When a request shares a prefix with a recent request, the server can reuse the already-computed K,V tensors for that prefix — skipping the forward pass entirely for those tokens. Only the new suffix needs computing. Cache typically expires after 5 minutes of inactivity.

PRICING IMPACT

Cached tokens cost ~10% of fresh tokens

Anthropic: cache writes cost 1.25× base input price, cache reads cost 0.1× base price. For a 10k-token system prompt reused across 100 calls: without caching ≈ 1M input tokens billed; with caching ≈ 10k (write) + 99×10k×0.1 (reads) ≈ 109k token-equivalents — a 9× cost reduction.

WHEN IT HELPS MOST

Long static context, short dynamic query

Best fit: large system prompts, RAG with the same retrieved documents across a session, codebase context for coding agents, multi-turn conversations replaying history. Doesn't help: every request has unique content with no shared prefix (e.g. single one-off translations).

SEMANTIC ENTROPY (KUHN ET AL. 2023)

Sample N times, cluster by meaning

Generate the same prompt N times at temperature >0. Cluster responses by semantic equivalence (not exact string match — "Paris" and "It's Paris" are the same cluster). Low entropy (all samples agree) → confident/likely correct. High entropy (samples disagree) → likely hallucinating.

TOKEN-LEVEL CONFIDENCE

Hallucinated facts have lower probability

When a model hallucinates a specific fact (a date, name, citation), the probability assigned to those specific tokens is often measurably lower than surrounding "safe" tokens — even though the model still outputs them. This signal is the basis of several commercial hallucination-detection APIs.

GROUNDING / ATTRIBUTION

Does the answer trace to source text?

For RAG systems: check whether claims in the answer are entailed by the retrieved chunks (using a separate NLI model or the LLM itself as a judge). Claims with no supporting span in context are flagged. This is the core mechanism behind citation features in production RAG products.

REFUSAL AS A DIRECTION (2024)

A single linear direction in activation space

Arditi et al. (2024) found refusal behavior is largely mediated by a single direction in the residual stream. Ablating this direction ("abliteration") removes most refusals with minimal capability loss — showing safety training is often shallow rather than deeply integrated.

MULTI-TURN EROSION

Gradual context manipulation

Rather than one harmful request, attackers build context across turns — establishing a fictional frame, getting small concessions, then escalating. Each individual turn looks benign; the cumulative trajectory crosses the line. Defending requires evaluating conversation-level intent, not just per-turn.

RED-TEAMING IN PRACTICE

Automated + human adversarial testing

Anthropic, OpenAI, and others run continuous red-teaming: automated adversarial prompt generation (sometimes using LLMs to attack LLMs), human red-teamers probing edge cases, and post-deployment monitoring for novel jailbreak patterns discovered "in the wild." This is an ongoing arms race, not a solved problem.
