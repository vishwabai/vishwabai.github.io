BUILDING BLOCKS

Start here: what does f(x) mean?

A function is a machine: feed it a number, it hands back another number. Everything in this deck is built from that one idea.

In this deck, "x" is usually data, and "f" is usually the model. Later, f will have millions of knobs — but it's still just a machine that turns inputs into outputs.
BUILDING BLOCKS

The derivative: how fast is the output changing?

Nudge the input a tiny bit and watch the output. The derivative is just: output change ÷ input change, as that nudge shrinks toward zero.

That's it — a derivative is a slope. Steep slope means the output reacts strongly to changes in the input; flat slope means it barely reacts at all.
BUILDING BLOCKS

What if there's more than one input?

A real model has millions of inputs (its weights). A partial derivative asks a simple question: wiggle just one of them, freeze all the others — how much does the output move?

Do this once for every parameter, and you get a whole list of these — one number per weight. That list is the gradient. Next slide.
BUILDING BLOCKS

Collect them all: the gradient ∇L

Stack every partial derivative into one list, in order. That list is called the gradient — and it points in the direction the loss grows fastest.

Every entry in this vector tells you exactly which way — and how strongly — to nudge that one parameter to make the loss go down.

LINEAR ALGEBRA BASICS

Before rank and LoRA: what is a matrix?

Just a grid of numbers, arranged in rows and columns. Nothing more mysterious than a spreadsheet.

A neural network's weight matrix is exactly this — just bigger. A 4096×4096 matrix is the same idea, 16.7 million cells instead of 12.
LINEAR ALGEBRA BASICS

Multiplying a vector by a matrix

Each output number is a dot product: multiply matching entries together, then add them up.

"y = xW" is just this process repeated for every output column — no matter how big the matrix gets.
LINEAR ALGEBRA BASICS

Two vectors can build a whole matrix

Take a column of numbers and a row of numbers. Multiply every pairing between them, and you get a full grid — from almost nothing.

This grid didn't come from nowhere — every entry is just uᵢ × vⱼ. A matrix built this way is called rank-1: the simplest, most "patterned" matrix there is.
LINEAR ALGEBRA BASICS

Add more pairs, get a richer matrix

One outer product only makes a patterned, "rank-1" matrix. Add a second one, a third — each addition makes the matrix more flexible.

This is the whole idea of "rank": how many rank-1 pieces does it take to build this matrix exactly? That count is its rank.
LINEAR ALGEBRA BASICS

Every matrix splits into three simpler pieces

This is called the SVD (Singular Value Decomposition). Any matrix — no matter how big — can be rebuilt from three special pieces multiplied together.

Σ is the important one for us: it's a diagonal list of numbers, sorted largest to smallest, telling you exactly how much each direction actually matters.
LINEAR ALGEBRA BASICS

Why keeping just a few pieces is enough

Since Σ's numbers are sorted biggest first, the first few rank-1 pieces usually carry almost all of the matrix's "meaning." The rest are small corrections.

A theorem called Eckart–Young proves this isn't a lucky guess — keeping the top-r pieces is mathematically the best possible rank-r approximation you could ever build.
FROM MATH TO LoRA

Now let's point all of this at fine-tuning

Fine-tuning means finding a correction matrix, ΔW, so that the pretrained weight W₀ becomes better at your task.

Full fine-tuning learns every entry of ΔW directly — same shape as W₀, same enormous parameter count. Section 10's lesson says: we probably don't need to.
FROM MATH TO LoRA

Apply the rank lesson to ΔW

We just saw: a handful of rank-1 pieces can rebuild a matrix almost exactly. So instead of learning all of ΔW, let's directly learn a small number of those pieces.

That's the entire idea behind LoRA. Nothing invented from thin air — just the SVD lesson, applied directly to the fine-tuning problem.

QLoRA MATH, FROM SCRATCH

One more basic idea: rounding to the nearest bucket

To store a number in fewer bits, you snap it to the closest value from a small fixed list of "buckets."

Fewer bits available = fewer buckets to choose from = a little rounding error each time. The only real design choice is: where do you place the buckets?
QLoRA MATH, FROM SCRATCH

Where should the buckets actually go?

Pretrained weights cluster near zero in a bell curve. A quantile is just a cut point that splits the area under that curve into equal-sized slices.

Near the center, slices are packed close together (lots of weights live there — fine detail matters). Out in the tails, slices spread wide (few weights, so less resolution is wasted there).
