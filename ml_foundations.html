A FEYNMAN WALKTHROUGH
Foundations of Machine Learning
If you can't build the intuition from scratch, you don't understand it yet.
Nine ideas. One connected story. Let's build it piece by piece.
The journey ahead
Each idea reveals the next: representation, uncertainty, estimation, search, error, and generalization.
PART 1
Linear Algebra
The language for representing data
Data is just an arrow
A vector is an ordered list of numbers — and, geometrically, a point (or arrow) in space.
Vectors combine by stacking movements
Add vectors tip-to-tail. This is literally how a neural network layer sums incoming signals.
How similar are two directions?
similarity = 0.10
As two vectors point the same way, their dot product — and similarity score — grows. This is how recommendation systems find "similar" songs or products.
A matrix moves the whole plane
A matrix stretches, rotates, or shears every point in space at once. This is exactly what a neural-network layer does to your data.
Multiplying is transforming, entry by entry
Each output is a weighted sum of every input. Every layer in a neural network is literally this operation, repeated.
Some directions don't rotate — they only stretch
Transform the whole ellipse, and this one direction only stretches by λ. The eigenvector with the biggest λ is the direction data varies most — that's the idea behind PCA.
So far: we can represent data as vectors, and transform it with matrices.
But real data is noisy and uncertain — how do we model what we don't know for sure?
→ Probability
PART 2
Probability
The language for representing uncertainty
Not every outcome is equally likely
Roll enough dice and outcomes pile up unevenly — that shape is a probability distribution. This is why we model house prices as a range, not a single guess.
Probability changes when you know more
P(A∩B) is the overlap. Zoom into just circle B, and the overlap's share of B is the conditional probability P(A|B) — "given it's cloudy, how likely is rain?"
Updating belief with evidence
Seeing evidence updates belief — the same math powers spam filters and how doctors read medical test results.
Probability lets us reason about uncertain outcomes — once we know the rules.
But in the real world, we never know the true distribution — we only have samples. How do we learn it?
→ Statistics
PART 3
Statistics
Learning the unknowns from data
Summarizing a cloud of numbers
Mean finds the center of mass. Variance measures how far, on average, points spread from it.
Why the bell curve shows up everywhere
Add up enough independent random things — dice rolls, measurement errors, user behaviors — and you always get this same bell shape. That's the Central Limit Theorem.
Finding the parameters that best explain the data
likelihood: 0.02
Slide the curve's center and width until the data becomes as likely as possible under it — that's Maximum Likelihood Estimation, the same idea behind "fitting a model."
Statistics lets us estimate the parameters — like that curve — that best explain our data.
But "best fit" can't be found by trial and error when a model has millions of parameters. How do we search efficiently?
→ Optimization
PART 4
Optimization
Finding the best parameters
Every set of parameters has a cost
loss = 8.40
Training a model means finding the lowest point on this landscape — the point of least loss.
Not all landscapes have one valley
A convex bowl always leads to the true minimum. A non-convex landscape can trap a search in a valley that isn't the lowest one.
The slope tells you which way is downhill
The derivative is the slope at a point. In many dimensions that slope becomes a gradient vector — and its negative points straight downhill.
The gradient tells us which direction is downhill on the loss landscape.
But knowing the direction once isn't enough — how do we actually reach the bottom, step by step?
→ Gradient Descent
PART 5
Gradient Descent
How optimization actually happens, step by step
Take a step, look again, repeat
Each step: check the slope, move a little downhill, repeat — until the steps get tiny and you've settled at the bottom.
The formula behind every step
Subtract a small fraction of the gradient from the current parameters, and repeat until it stops changing much.
Step size matters more than you'd think
Too small: crawls forever. Too big: overshoots and bounces around, sometimes diverging. Just right: settles smoothly.
How much data per step?
Full batch — uses every point each step
Full-batch is smooth but slow per step. Stochastic (one point) is fast but noisy. Mini-batch — a small random group — is the practical middle ground almost everyone uses.
Remembering where you've been
Plain gradient descent jitters back and forth in narrow valleys (red). Momentum carries velocity forward, smoothing and speeding the path (green) — the core trick behind Adam and friends.
Gradient descent walks downhill on the loss landscape, one careful step at a time.
But we've been saying "loss" as if it's obvious — what exactly are we measuring?
→ Loss Functions
PART 6
Loss Functions
Defining what "best" even means
The gap between prediction and truth
loss = 0
Loss is just: how wrong were we, turned into a single number we can minimize.
Squaring the error — punishing big mistakes more
Mean Squared Error: measure each residual, square it (punishing outliers hard), and average. Used for regression — predicting continuous values like price or temperature.
Penalizing confident wrong answers
As predicted confidence in the correct class drops toward zero, loss explodes. Used for classification — like recognizing digits or images.
Loss functions measure exactly how wrong a model's predictions are.
But minimizing loss on the data we have isn't the same as being right on new data. What goes wrong?
→ Overfitting & Underfitting
PART 7
Overfitting & Underfitting
When "low loss on training data" isn't enough
Too simple to see the pattern
A straight line can't follow this curve. High bias: the model is too rigid, and it's wrong almost everywhere — on training data and new data alike.
Too flexible — memorizing the noise
Same data — but now the curve contorts to pass through every point exactly. High variance: perfect on this data, wild and unreliable on new data.
Watch two curves diverge
Training loss always keeps falling. Validation loss falls, then rises — that turning point is where overfitting begins. Stopping there is called early stopping.
Overfitting happens when a model has too much freedom to chase noise.
Can we keep a flexible model, but discourage it from getting too wild?
→ Regularization
PART 8
Regularization
Keeping models honest
Add a cost for complexity itself
Now the model pays a price for having large weights — it must earn every bit of complexity by actually reducing error.
L2 (Ridge): shrinking weights smoothly
λ = 0.0
As λ grows, every weight shrinks toward zero smoothly — none reach exactly zero. Geometrically, the penalty is a circular boundary the weights can't cross.
L1 (Lasso): pushing weak weights to exactly zero
L1's sharp corners let the optimal point land exactly on an axis — some weights vanish completely. That's automatic feature selection.
Regularization trades a little training fit for a lot of generalization.
Underfitting, overfitting, regularization — is there one idea underneath all of it?
→ The Bias–Variance Tradeoff
PART 9
Bias–Variance Tradeoff
The idea underneath everything we just built
Bias: consistently off-target
All throws land tightly together — but consistently off to one side. That's bias: a systematic error, the same mistake made every time.
Variance: inconsistent, scattered
This time throws average out near the center — but each individual one lands somewhere wildly different. That's variance: high sensitivity to which data you happened to train on.
Balancing both is the real skill
Total error = bias² + variance + irreducible noise. Too simple → bias dominates. Too complex → variance dominates. The best model sits at the minimum of the U — exactly what regularization and early stopping search for.
The full pipeline, in one picture
Represent data → model uncertainty → estimate parameters → search the landscape → walk it with gradients → measure error → watch for overfitting → regularize → balance bias and variance. Every ML model you'll ever build walks this same path.
