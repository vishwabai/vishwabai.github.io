A From-Scratch Derivation

The Math Of RL, Built From Scratch

No equation appears out of nowhere. Every formula here starts from something you already know, and grows one honest step at a time into the real thing.

Starting From The Very Beginning

What Is A Variable, Really?

A variable is just a labeled box holding a number. When you see "x" in an equation, mentally replace it with whatever number is currently sitting in that box. That's the entire idea — everything below is built out of nothing more than this.

One Symbol You'll See Everywhere

What Does Σ (Sigma) Actually Do?

Σᵢ₌₁³  i
means: "add up i, for i = 1, then i = 2, then i = 3"
= 1 + 2 + 3
= 6

That's it — Σ is just shorthand for "write out a list of numbers and add them." Every Σ you'll see later expands exactly this same way, just with different things being added.

The Other Idea We'll Need

What Is A Probability?

A probability is a number between 0 and 1 describing how likely something is. If you list every possible outcome of a situation, their probabilities always add up to exactly 1 — the whole pie is accounted for, nothing more, nothing less.

Building Toward Expectation

From Plain Average To Weighted Average

plain average of a, b, c  =  (a + b + c) / 3
this secretly already IS a weighted average — each one just happens to get the same weight, 1/3
= ⅓·a + ⅓·b + ⅓·c
now let the weights differ — replace each ⅓ with its own probability p
𝔼[X]  =  p₁·x₁ + p₂·x₂ + p₃·x₃  =  Σᵢ pᵢ·xᵢ
Why We Bother With This

Rewards Are Random — So We Need An Average

The same action, in the same state, doesn't always produce the same reward — the world has randomness in it. So "how good is this action" can't be a single observed reward; it has to be an average over every way things could turn out. That average is exactly the 𝔼[X] we just built.

Building The Return — Step 1

Start With The Simplest Possible Idea

"how good is the future from here?" — simplest possible answer: just add up every future reward
G_t  =  r₁ + r₂ + r₃ + ⋯

This is a completely reasonable first guess. The next two slides show exactly what goes wrong with it, and how to fix it.

Building The Return — Step 2

The Problem: This Sum Can Explode

if rewards never stop:  G_t = 1 + 1 + 1 + 1 + ⋯  =  ∞
an infinite value can't be compared to anything, or improved, or optimized — we need every future to add up to some finite number
fix: shrink each future term a little more than the last
Building The Return — Step 3

Add The Discount γ

G_t  =  r₁ + γr₂ + γ²r₃ + γ³r₄ + ⋯   (0 ≤ γ < 1)
since γ<1, this is a geometric series — guaranteed to add up to a finite number: at most R_max /(1−γ)
e.g. γ=0.9, rewards capped at 1  →  G_t ≤ 1/(1−0.9) = 10, never infinite
Two Pieces, Combined

From Return To Value Function

have: G_t (slide 9)  +  𝔼[·] (slide 5)
the return is random (the world is random); average it, exactly the way we averaged the spinner
V(s)  =  𝔼[ G_t  |  s_t = s ]

Nothing new was invented on this slide — V(s) is just "the weighted average" applied to "the total future reward," both of which you already built.

Building The Bellman Equation — Step 1

Split Off The First Reward

G_t = r₁ + γr₂ + γ²r₃ + γ³r₄ + ⋯
= r₁  +  γ(r₂ + γr₃ + γ²r₄ + ⋯)
the part in parentheses is just G_{t+1} — the exact same kind of sum, starting one step later
G_t  =  r₁ + γ·G_{t+1}

This is pure algebra — just factoring γ out of the second term onward. No RL-specific assumption has been used yet.

Building The Bellman Equation — Step 2

Take The Expectation Of Both Sides

G_t = r₁ + γ·G_{t+1}
apply 𝔼[· | s_t=s] to both sides — allowed because expectation of a sum is the sum of expectations
𝔼[G_t|s_t=s]  =  𝔼[r₁|s_t=s] + γ·𝔼[G_{t+1}|s_t=s]
Building The Bellman Equation — Step 3

Spot The Self-Reference

the left side, 𝔼[G_t|s_t=s], is exactly V(s) — from slide 10
and 𝔼[G_{t+1}|s_{t+1}=s'] is ALSO exactly V — of the state one step later, V(s')
V(s)  =  𝔼[ r + γV(s')  |  s_t = s ]

V now appears on both sides of its own definition. That's the entire Bellman equation — not a new idea, just noticing that the same function shows up twice when you expand the return by one step.

Why Bother Noticing This

The Payoff Of The Self-Reference

Because V(s) only depends on one real reward plus the value of the very next state, you never need to see how an entire episode ends to improve your estimate. You can learn from a single step of experience — this one fact is the foundation of every learning rule that follows.

One Small Change, One Big Consequence

From "Evaluate A Policy" To "Find The Best"

V(s) = 𝔼_π[ r + γV(s') ]   — averages over whatever the policy happens to choose
what if, instead of averaging over the policy's choices, we always assumed the single best action was taken?
V*(s)  =  maxₐ  𝔼[ r + γV*(s') ]

Swap "average over π" for "max over a," and you've gone from describing one specific policy to defining the best possible value achievable by any policy at all.

Building Q-Learning — Step 1

We Can't Actually Compute That Average

V*(s) = maxₐ 𝔼[r + γV*(s')] requires knowing every possible next state and how likely each one is — the full rules of the world. In practice, we usually only get to see one real transition (s, a, r, s') at a time. We need a version of this equation that works from just that one sample.

Building Q-Learning — Step 2

Turn The Equation Into An Update Rule

true equation:  Q*(s,a) = 𝔼[r + γ·maxₐ' Q*(s',a')]
replace the unknown expectation with ONE observed sample — a noisy, one-shot estimate
target  =  r + γ·maxₐ' Q(s',a')
don't overwrite Q with this noisy target — nudge toward it a little, by a step size α
Q(s,a)  ←  Q(s,a) + α[ target − Q(s,a) ]
Building Q-Learning — Step 3

Why Repeating This Actually Learns The Truth

Any single sample is noisy — sometimes the target overshoots, sometimes it undershoots. But nudging by a small α means each update only moves partway. Repeated over thousands of visits to the same (s,a), the noise averages out, and Q(s,a) settles onto the true expected value — exactly the way averaging many spins of the wheel, back on slide 5, settled onto the true 𝔼[X].

The Whole Chain, In One Place

From A Single Sigma To Q-Learning

Σ, probability  →  weighted average 𝔼[X]  →  return G_t = r + γr + γ²r + ⋯
𝔼[X] + G_t  →  V(s) = 𝔼[G_t|s]  →  split G_t  →  Bellman: V(s) = 𝔼[r + γV(s')]
swap average for max  →  V*(s) = maxₐ 𝔼[r+γV*(s')]  →  one sample + a nudge  →  Q-learning

Every arrow above is a single, small, honest step — nowhere did a formula appear without you already having built the piece it's made of.

You Just Did This

You Derived Q-Learning From Scratch

Starting from nothing but "add up a list of numbers" and "a number between 0 and 1," you built the weighted average, the return, the value function, the Bellman equation, and finally the Q-learning update — the same equation that trains real game-playing and robotic agents today.

That's the whole trick behind every equation in this series: nothing is magic, everything is buildable.
