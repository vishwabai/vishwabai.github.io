00 — orientation

What you're actually looking at

A GPT is a function that takes a sequence of tokens and outputs, for every position, a probability distribution over "what character comes next." It does this by turning each character into a vector (an embedding), then repeatedly letting positions look at each other (attention) and think privately (MLP), updating a running vector per position called the residual stream. At the end it reads the residual stream back out as character probabilities. That's the entire idea — everything below is that idea, instrumented so you can watch it happen.

Because real embeddings are 24+ numbers per token that mean nothing to a human eye, every visualization below also decodes the residual stream back into its nearest character at each stage — a real interpretability technique called the logit lens (project the intermediate vector through the model's own final layer norm + unembedding matrix, and read off the argmax). It's not a fake illustration; it's the same computation the model itself ends each layer with, just run early.

01 — the math

Every equation the model runs, and why it's shaped that way

Six operations, repeated and composed, are the entire model. For each one: the formula, the tensor shapes flowing through it, why it's defined that way and not some other way, and exactly which function above (and line of the PyTorch code in §05) computes it.

1 · Token & positional embeddingturn symbols into geometry
xi  =  Wte[ti]  +  Wpe[i]for every position i = 0, 1, …, T−1
W_te ∈ ℝ^(V×d)  ·  W_pe ∈ ℝ^(T_max×d)  ·  x_i ∈ ℝ^d  ·  here d=24, V=–

Why a lookup table, not a formula: a character has no inherent numeric meaning — "q" isn't "greater than" or "close to" any other letter. So instead of hand-designing a representation, we give every token a free vector and let gradient descent place it wherever is useful for prediction. After training, tokens that behave similarly in context end up geometrically close, purely as a side effect of minimizing loss — meaning emerges from usage, not definition.

Why add a position vector at all: attention (below) computes a weighted sum over other positions' values — sums don't know order (Attention(shuffle(X)) is just a shuffle of Attention(X)). A transformer without positional information genuinely cannot tell "cat sat" from "sat cat". Adding a learned vector per position breaks that symmetry: position 0's vector is now geometrically distinguishable from position 1's, everywhere downstream.

→ implemented by embedLookup(p.wte, idxs) + embedLookup(p.wpe, positions) in Part B above · rendered as the "embed" heatmap in §03
2 · Scaled dot-product self-attentionlet positions read each other
Q = XWQ    K = XWK    V = XWV
Attention(Q,K,V)  =  softmax( QK⊤√dk + M ) V
X ∈ ℝ^(T×d)  ·  Q,K,V ∈ ℝ^(T×d_k)  ·  QK^⊤ ∈ ℝ^(T×T)  ·  M = causal mask, T×T
  1. Q, K, V are three learned projections of the same input. Query = "what am I looking for," Key = "what do I contain," Value = "what do I actually pass along if attended to." Splitting one vector into three roles is what lets a token search for context without that search overwriting its own content.
  2. QK⊤ is a similarity matrix. Row i, column j is the dot product of query i and key j — large when the two vectors point in a similar direction, i.e. "position i thinks position j is relevant." This is exactly the (T×T) heatmap you'll see in §03.
  3. Divide by √dk. If Q and K have unit-variance random entries, each dot product sums dk such terms, so its variance grows linearly with dk. Un-scaled, dot products get large in magnitude as dimension grows, which pushes softmax into a saturated regime where one entry ≈ 1 and the rest ≈ 0 — gradients vanish everywhere except that one spike. Dividing by √dk keeps the variance ≈ 1 regardless of dimension, so softmax stays in a well-conditioned range early in training.
  4. Add the causal mask M (0 on/below the diagonal, −∞ above it) before the softmax. Since e−∞ = 0, this deterministically zeroes out attention to every future position — the mathematical enforcement of "predict the next token using only what came before it," which is the entire reason this is called an autoregressive model.
  5. softmax(·) turns scores into a probability distribution over which positions to read from — each row sums to 1. Attention·V is then literally a weighted average of every earlier position's value vector, weighted by relevance.
headh = Attention(XWQ(h), XWK(h), XWV(h))
MultiHead(X) = Concat(head₁, …, headH) WO

Why multiple heads instead of one big attention: one attention pattern can only express one notion of "relevant" per layer. Splitting d into H independent, narrower attention computations lets different heads specialize — one might track "the previous vowel," another "the start of the current word," another something with no clean English name at all — and the results are concatenated back to full width before being mixed by WO.

→ implemented by attention() in Part B: matmul, scaleV, addConst (the mask), softmaxRows · visualized per-block in §03
3 · Layer normalizationkeep every layer's numbers well-behaved
x − μ√(σ² + ε) = x̂     LN(x) = γ⊙x̂ + β
μ, σ² computed per token, across the d feature channels  ·  γ, β ∈ ℝ^d, learned

Why normalize at all: as a signal passes through many stacked layers, its scale can drift — repeated matrix multiplies can shrink or blow up activations layer over layer, which makes gradients unstable during training (the classic vanishing/exploding gradient problem). Forcing every token's vector to zero mean and unit variance before each sub-layer keeps the numeric scale consistent no matter how deep the stack gets, which in practice is what makes it possible to train 96-layer transformers at all.

Why γ, β afterward: forcing exactly mean-0/variance-1 might be too restrictive for what a given layer needs to represent — γ and β let the network learn to rescale and re-shift back to whatever distribution is actually useful, while still getting the stability benefit during the normalization step itself.

Pre-norm placement: this model normalizes before attention/MLP (x + attn(LN(x))) rather than after, exactly like GPT-2 and nanoGPT. Post-norm (the original 2017 Transformer paper's choice) puts LayerNorm on the residual path itself, which empirically makes very deep models harder to train; pre-norm keeps the residual path a clean, unimpeded identity highway (see point 4) and only normalizes the branch being added to it.

→ implemented by layerNorm() in Part A · applied as ln1/ln2/ln_f in every block
4 · Residual (skip) connectionslet gradients — and information — skip layers
x(l+1) = x(l) + f(x(l))

The calculus reason this matters: by the chain rule, ∂x(l+1)/∂x(l) = I + ∂f/∂x(l). That leading identity matrix I means a gradient flowing backward always has a direct, unattenuated path all the way back to the input, no matter how many blocks sit in between — the "+ f(x)" term can only add further gradient signal, never multiply the direct path away to zero. This is precisely why transformers can be stacked 10, 50, even 100+ layers deep and still train: without residual connections, gradients would have to survive being multiplied by every layer's Jacobian in sequence, and in practice that product shrinks toward zero.

The representational reason: each block only has to learn a correction to the residual stream ("attend to something and add a small adjustment"), not reinvent the whole representation from scratch. This is why it's called a residual stream: information written in early layers persists by default and is only ever added to, unless a later layer specifically learns to cancel it out.

→ implemented by the two add(x, …) calls per block in forward(), Part B
5 · Position-wise feed-forward network (MLP)private compute, per position
MLP(x) = GELU(xW1) W2     W1 ∈ ℝd×4d,   W2 ∈ ℝ4d×d
GELU(x) ≈ 0.5x·( 1 + tanh[ √(2/π)·(x + 0.044715x3) ] )

Division of labor: attention is the only place information moves between positions — it's a weighted sum, which means it's fundamentally linear in V. The MLP runs on every position independently (no T×T mixing at all) and is where the actual nonlinear computation happens: "given what I now know after reading context, transform it." A common intuition: attention routes information, the MLP computes with it.

Why expand to 4d and back: the up-projection to a wider hidden dimension gives the nonlinearity more room to carve up the space before compressing back down — empirically found to work well in the original Transformer paper and kept as a convention since; it's roughly two-thirds of a transformer's total parameters, and where most of its raw capacity to memorize patterns lives.

Why GELU instead of plain ReLU: ReLU hard-zeroes every negative input, discarding gradient information for any unit that happens to be off. GELU is a smooth curve that weights inputs by their value and a probability of being "kept" (its own name — Gaussian Error Linear Unit — comes from that probabilistic derivation), which in practice trains slightly better for transformers and is what GPT-2 and nanoGPT both use.

→ implemented by mlp() in Part B, using geluV() from Part A
6 · Unembedding, softmax, and the lossturn the final vector into "how wrong were you"
z = LN(x) Wte⊤     pi = eziΣj ezj     L = −log ptarget

Weight tying — reusing Wte transposed: the same matrix that turned token ids into vectors is reused, transposed, to turn the final vector back into scores over the vocabulary. It works because both directions are asking a related question — "how much does this direction in space resemble token k's meaning" — so tying them halves the parameter count and, empirically, also improves quality by forcing input and output representations to live in one consistent space.

The elegant part — why softmax and cross-entropy are always paired: written separately, differentiating softmax then cross-entropy through the chain rule requires the full softmax Jacobian (an n×n matrix, since every output probability depends on every input logit). But combined, the gradient collapses to something almost embarrassingly simple: ∂L/∂zi = pi − 𝟙[i = target] — literally "predicted probability minus 1 at the correct class, minus 0 everywhere else." That's the entire backward pass for the output layer: subtract a one-hot vector from the probability vector. It's cheap, numerically stable, and exactly what crossEntropy()'s _backward computes in Part A above.

→ implemented by crossEntropy() in Part A · the softmax(z) itself is what the "final distribution" bar chart in §03 shows
7 · Backpropagation — how every gradient above actually gets computedthe chain rule, mechanized
ū = ∂L∂u =  Σv : u→v  v̄ · ∂v∂u

Every operation above — matmul, add, layerNorm, softmaxRows, gelu — is a node in a computation graph. Reverse-mode autograd (what .backward() does in PyTorch, and what backwardPass() does in Part A of this page) works in exactly two passes:

  1. Forward pass: run the computation normally, but every operation remembers its inputs and which operation produced it — building a DAG (directed acyclic graph) as a side effect of just doing the math.
  2. Topological sort: order every node so that each one appears after all the nodes that feed into it — guaranteeing that by the time we compute a node's gradient, every node downstream of it has already been processed.
  3. Backward pass: starting from the loss (whose gradient with respect to itself is trivially 1), walk the topological order in reverse. At each node, take the gradient flowing in from above (v̄, how much the loss changes per unit change in this node's output) and use that node's own local derivative rule to push gradient onto its own inputs. A matmul's local rule is another matmul (with a transpose); softmax's local rule is a Jacobian-vector product; layernorm's is the messier formula baked into layerNorm()'s _backward — but every single one is just "how does a small nudge to my input change my output," applied mechanically.
  4. Accumulate into leaves: parameters (the W's, γ's, β's, embedding tables) are the graph's leaf nodes. Once the backward pass finishes, each parameter's .grad holds exactly ∂Loss/∂parameter — the direction that would make the loss worse fastest if you moved the parameter that way.

This is the entire mechanism. There is no separate "understanding" step — every weight in the network only ever changes because some chain of local derivative rules connected it, however indirectly, to the final loss number. Intelligence-as-behavior, if it emerges, emerges purely from millions of these tiny local nudges compounding over billions of training steps.

→ implemented by backwardPass() in Part A · every op's _backward closure is exactly step 3, specialized to that op
8 · The optimizer stepturn a gradient into a weight update
θ ← θ − η∇θLplain SGD — what this page uses
mt = β₁mt−1 + (1−β₁)gt    vt = β₂vt−1 + (1−β₂)gt²    θ ← θ − η m̂t√v̂t + εAdamW — what real nanoGPT uses

Why this page uses plain SGD: with a model this small, minimizing implementation surface area matters more than convergence speed — plain "subtract the gradient, scaled by a learning rate η" is exactly the formula in every trainSteps() update loop above, and it's enough to visibly drive the loss down in a few hundred steps.

Why real GPT training uses Adam(W) instead: Adam keeps a running average of each parameter's gradient (m, momentum — smooths out noisy per-batch gradients) and of its squared gradient (v, variance — lets parameters with consistently small gradients take larger steps and vice versa). In practice this converges faster and is far less sensitive to the exact learning rate than plain SGD is, which matters enormously when a single training run costs actual GPU-hours and you can't afford many restarts to find a good η by trial and error.

    xb, yb = get_batch('train')              # (B, T) random windows + their targets
    logits = model(xb)                          # (B, T, vocab_size)
    loss = F.cross_entropy(logits.view(-1, vocab_size), yb.view(-1))

    loss.backward()                             # exactly what backward() does below, but autograd is PyTorch's

03 — forward pass

Push text through every layer

Type a short prompt (it'll be clipped to the model's context window) and run it through the network. You'll see the token embeddings, then — block by block — the causal attention pattern, the residual stream after attention and after the MLP, and the logit-lens guess at every position.

step 1 — tokenize

Each character maps to an integer id via a fixed lookup table built from the training corpus's alphabet. This is the entire "tokenizer" — real GPTs use sub-word tokenizers (byte-pair encoding) over ~50,000 tokens; we use raw characters so every step stays human-readable.

step 2 — embed + positional encoding

Each token id looks up a learned row in the embedding table wte (token meaning), and is added to a learned row in wpe (position in the sequence). The sum is the model's starting representation for that position — the first state of the residual stream.

04 — autoregressive generation

Sample, append, repeat

Generation is just the forward pass above, run over and over: predict a distribution for the next character, sample one (temperature controls how greedy vs. random), append it to the context, and feed the whole thing back in. There is no separate "writing" mechanism — it is one-token-at-a-time prediction, all the way down.

model.py — causal self-attention (the part that does the "looking at other tokens")
class CausalSelfAttention(nn.Module):
    def __init__(self, n_embd, n_head, block_size):
        super().__init__()
        self.n_head = n_head
        self.c_attn = nn.Linear(n_embd, 3 * n_embd)   # produces Q, K, V in one matmul
        self.c_proj = nn.Linear(n_embd, n_embd)        # output projection (Wo above)
        mask = torch.tril(torch.ones(block_size, block_size))
        self.register_buffer("mask", mask.view(1, 1, block_size, block_size))

    def forward(self, x):                      # x: (B, T, C)
        B, T, C = x.shape
        q, k, v = self.c_attn(x).split(C, dim=2)
        hd = C // self.n_head
        q = q.view(B, T, self.n_head, hd).transpose(1, 2)   # (B, nh, T, hd)
        k = k.view(B, T, self.n_head, hd).transpose(1, 2)
        v = v.view(B, T, self.n_head, hd).transpose(1, 2)

        att = (q @ k.transpose(-2, -1)) / math.sqrt(hd)      # (B, nh, T, T) — raw attention scores
        att = att.masked_fill(self.mask[:, :, :T, :T] == 0, float('-inf'))  # causal mask: can't see the future
        att = F.softmax(att, dim=-1)                          # this row is exactly the heatmap you saw above
        y = att @ v                                            # weighted sum of value vectors
        y = y.transpose(1, 2).contiguous().view(B, T, C)
        return self.c_proj(y)
model.py — the block (attention + MLP, pre-norm, residual)
class Block(nn.Module):
    def __init__(self, n_embd, n_head, block_size):
        super().__init__()
        self.ln1 = nn.LayerNorm(n_embd)
        self.attn = CausalSelfAttention(n_embd, n_head, block_size)
        self.ln2 = nn.LayerNorm(n_embd)
        self.mlp = nn.Sequential(
            nn.Linear(n_embd, 4 * n_embd),
            nn.GELU(),
            nn.Linear(4 * n_embd, n_embd),
        )

    def forward(self, x):
        x = x + self.attn(self.ln1(x))   # residual stream: add, never replace
        x = x + self.mlp(self.ln2(x))
        return x
model.py — full GPT (embed → blocks → unembed)
class GPT(nn.Module):
    def __init__(self, vocab_size, block_size,
                 n_embd=24, n_head=3, n_layer=3):
        super().__init__()
        self.wte = nn.Embedding(vocab_size, n_embd)
        self.wpe = nn.Embedding(block_size, n_embd)
        self.blocks = nn.ModuleList(
            [Block(n_embd, n_head, block_size) for _ in range(n_layer)])
        self.ln_f = nn.LayerNorm(n_embd)
        # weight tying: reuse wte as the unembedding matrix
        self.lm_head = nn.Linear(n_embd, vocab_size, bias=False)
        self.lm_head.weight = self.wte.weight

    def forward(self, idx):
        B, T = idx.shape
        pos = torch.arange(T, device=idx.device)
        x = self.wte(idx) + self.wpe(pos)     # the FIRST residual stream state
        for block in self.blocks:
            x = block(x)
        x = self.ln_f(x)
        return self.lm_head(x)               # (B, T, vocab_size) logits

This is, deliberately, ~95% of what nanoGPT's model.py contains — Andrej Karpathy's real reference implementation just adds dropout, bias terms, Flash Attention for speed, and KV-caching for fast generation. Everything structural is above.

06 — from here to a real LLM

What actually changes as this scales up

Nothing about the architecture changes between this toy and GPT-2/GPT-3-scale models — only the numbers, the tokenizer, and the engineering around them:

what stays identical

Embedding → N×(attention, MLP) → LayerNorm → unembed. Causal masking. Residual connections. Cross-entropy training on "predict the next token." Weight tying. Literally the code above.

what scales up

n_embd: 24 → 768–12288. n_layer: 3 → 12–96+. n_head: 3 → 12–96. block_size (context): 16 → 2048–1,000,000+. Training tokens: hundreds of characters → trillions of sub-word tokens.

what gets added in practice

Byte-pair-encoding tokenizer (vocab ~50k subwords instead of ~30 characters). AdamW with learning-rate warmup + cosine decay. Dropout. Mixed precision + multi-GPU sharding. Flash Attention (same math, fused kernel). RLHF / instruction-tuning after this pretraining stage, to turn "predicts plausible text" into "follows instructions."

the honest one-sentence summary

An LLM is this exact loop — predict the next token, compute how wrong you were, nudge every weight to be slightly less wrong, repeat billions of times — at a scale large enough that "slightly less wrong at predicting text" becomes "models grammar, facts, reasoning patterns, and style."

Suggested path if you want to build this for real, Karpathy-style: 1) implement micrograd (scalar autograd) by hand — you basically just did the matrix version of this above. 2) Implement makemore (bigram → MLP → tiny attention) on a real text corpus. 3) Run the attached train.py on a GPU with a real BPE tokenizer (e.g. tiktoken) over a few-MB text file (Tiny Shakespeare is the classic first dataset). 4) Scale up n_layer/n_embd as compute allows.
