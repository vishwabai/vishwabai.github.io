Chapter 1

Why attention replaced RNNs

Before transformers, we used RNNs (recurrent neural networks) to process sequences. They worked by passing a hidden state from one token to the next — like a game of telephone. The problem: information about the first token had to survive 100+ steps of transformation to reach the last token. It rarely did.

The RNN problem

O(n) path length between tokens. After 8 steps the hidden state retains only ~5% of the first token's information. The gradient vanishes. Deep sequences break completely.

Attention solves this with a direct O(1) path between any two tokens. "The ancient king who ruled the land died" — "died" can attend directly to "ancient" regardless of distance, with 89% attention weight.

The key equation

Attention(Q, K, V) = softmax( Q·Kᵀ / √d_k ) · V — published in "Attention is All You Need" (Vaswani et al., 2017)

Chapter 2

Tokenization — BPE

Before any matrix exists, raw text must become integers. Byte-pair encoding (BPE) starts with individual characters and greedily merges the most frequent adjacent pairs, building a vocabulary of subword tokens.

GPT-4 uses the cl100k_base tokenizer with 100,277 tokens built from 50,000+ merge operations on a massive multilingual corpus.

why BPE
Handles any language, rare words, and code gracefully. Unknown words decompose into known subwords.
vocab size
Character-level: ~65. Word-level: 50k+. BPE: ~32k–100k. Goldilocks tradeoff.
when it runs
Once, before any matrix operations. Raw text never enters the model.
2024 research
tiktoken (OpenAI), SentencePiece (Google). GPT-4 cl100k_base has 100,277 tokens.

Chapter 3

Embeddings — integers become vectors

An integer ID like 2847 is just a label. It has no geometry, no concept of similarity. The embedding layer converts each integer into a high-dimensional vector — a point in n-dimensional space where similar concepts cluster together.

Two lookup tables: the token embedding table maps character IDs to vectors (what the token means), and the position embedding table maps positions to vectors (where the token sits). They're added together: x = tok_emb(idx) + pos_emb(positions).

# token embedding: vocab_size × n_embed matrix
self.tok_emb = nn.Embedding(vocab_size, n_embed)
# position embedding: block_size × n_embed matrix
self.pos_emb = nn.Embedding(block_size, n_embed)

def forward(self, idx):
    B, T = idx.shape
    tok = self.tok_emb(idx)              # (B, T, n_embed)
    pos = self.pos_emb(torch.arange(T))  # (T, n_embed)
    x = tok + pos                        # broadcast add → (B, T, n_embed)
    return x

Chapter 4

Positional encoding

Without positional information, "dog bites man" and "man bites dog" would look identical to the model — same tokens, same embeddings. Positional encoding stamps each position with a unique fingerprint.

The original transformer uses sine and cosine waves at different frequencies: PE(pos, 2i) = sin(pos / 10000^(2i/d)). Modern models (LLaMA, Mistral, GPT-NeoX) use RoPE — rotary position embeddings — which rotate the Q and K vectors by a position-dependent angle, baking position directly into the attention score.

Why RoPE wins (2024)

RoPE encodes relative positions in the Q·K dot product, so it generalises better to longer sequences than learned or fixed absolute positional encodings. Adopted by every major open-source LLM as of 2024.

Chapter 5

Scaled dot-product attention

Each token creates three vectors from its embedding: Query ("what am I looking for?"), Key ("what do I contain?"), and Value ("what do I send if attended to?"). These are produced by three weight matrices learned during training.

class Head(nn.Module):
    def __init__(self, head_size):
        super().__init__()
        self.key   = nn.Linear(n_embed, head_size, bias=False)
        self.query = nn.Linear(n_embed, head_size, bias=False)
        self.value = nn.Linear(n_embed, head_size, bias=False)
        self.register_buffer('tril',
            torch.tril(torch.ones(block_size, block_size)))

    def forward(self, x):
        B, T, C = x.shape
        k = self.key(x)    # (B, T, hs)
        q = self.query(x)  # (B, T, hs)
        wei = q @ k.transpose(-2, -1) * C**-0.5  # scale by 1/√d_k
        wei = wei.masked_fill(self.tril[:T,:T]==0, float('-inf'))
        wei = F.softmax(wei, dim=-1)
        v   = self.value(x)
        out = wei @ v
        return out
Why scale by 1/√d_k?

Without scaling, large head sizes cause dot products to grow huge → softmax saturates → gradients ≈ 0 → no learning. Dividing by √d_k keeps the distribution learnable. (Vaswani et al., 2017)

Chapter 6

Multi-head attention

Instead of one attention head, we run n_head heads in parallel — each looking at the sequence through a different learned "lens." One head might learn subject–verb links, another pronoun references, another local word proximity. Each head gets a smaller slice of the embedding (head_size = n_embed / n_head = 32/4 = 8 dims), runs its own Q·K·V computation, then all outputs are concatenated and projected back.

class MultiHead(nn.Module):
    def __init__(self, n_heads, head_size):
        super().__init__()
        self.heads = nn.ModuleList(
            [Head(head_size) for _ in range(n_heads)])
        self.proj  = nn.Linear(n_embed, n_embed)
    def forward(self, x):
        out = torch.cat([h(x) for h in self.heads], dim=-1)
        return self.proj(out)

Chapter 7

Feed-forward network (FFN)

After attention (which decides who to listen to), each token's vector passes through a two-layer MLP called the FFN (which decides what to think about what it heard). The FFN expands to 4× the embedding width, applies ReLU, then compresses back — giving the model room to store and combine features.

Research by Geva et al. (2021) showed that individual FFN neurons can be probed to reveal specific factual knowledge stored inside them. "Paris" → "capital" is stored in a particular weight pattern in the FFN, not the attention layers.

class FFN(nn.Module):
    def __init__(self):
        super().__init__()
        self.net = nn.Sequential(
            nn.Linear(n_embed, 4 * n_embed),  # 32 → 128  expand
            nn.ReLU(),                          # non-linearity
            nn.Linear(4 * n_embed, n_embed),  # 128 → 32  compress
        )
    def forward(self, x): return self.net(x)

Chapter 8

Residual connections + LayerNorm

Two stabilisation techniques make deep transformers trainable:

Residual (skip) connections: x = x + sublayer(x). The sublayer only learns what to add to x, not the full transformation. This gives gradients a direct highway back through the network, preventing vanishing.

LayerNorm: After each sublayer, normalise the vector to zero mean and unit variance. Without this, some dimensions explode while others vanish, making training unstable. Modern transformers (GPT-2+) use pre-norm: LayerNorm before the sublayer, not after.

Chapter 9

The complete transformer block

One transformer block = attention + FFN, each wrapped in a residual + LayerNorm. This unit repeats N times (our MicroGPT uses 3, BERT uses 12, GPT-3 uses 96).

class Block(nn.Module):
    def __init__(self):
        super().__init__()
        self.sa  = MultiHead(n_head, n_embed // n_head)
        self.ffn = FFN()
        self.ln1 = nn.LayerNorm(n_embed)
        self.ln2 = nn.LayerNorm(n_embed)
    def forward(self, x):
        x = x + self.sa(self.ln1(x))   # communicate
        x = x + self.ffn(self.ln2(x))  # think
        return x

The residual stream metaphor: x flows like a river, with each layer adding a tributary of new information without replacing what came before.

Chapter 10

Forward pass

During a forward pass, an input sequence flows left-to-right through every layer, producing a probability distribution over the vocabulary at each position. The model predicts the next token from that distribution.

class MicroGPT(nn.Module):
    def __init__(self):
        super().__init__()
        self.tok_emb  = nn.Embedding(vocab_size, n_embed)
        self.pos_emb  = nn.Embedding(block_size, n_embed)
        self.blocks   = nn.Sequential(*[Block() for _ in range(n_layer)])
        self.ln_final = nn.LayerNorm(n_embed)
        self.lm_head  = nn.Linear(n_embed, vocab_size)

    def forward(self, idx, targets=None):
        B, T = idx.shape
        x = self.tok_emb(idx) + self.pos_emb(torch.arange(T))
        x = self.blocks(x)
        x = self.ln_final(x)
        logits = self.lm_head(x)          # (B, T, vocab_size)
        loss = None
        if targets is not None:
            B, T, C = logits.shape
            loss = F.cross_entropy(
                logits.view(B*T, C), targets.view(B*T))
        return logits, loss

Chapter 11

Loss function — cross-entropy

After the forward pass, we compare the model's prediction to the true next token using cross-entropy loss: loss = −log(p_correct). The −log curve punishes confident wrong predictions exponentially harder than uncertain ones.

p = 0.10

Chapter 12

Backpropagation

After computing the loss, we need to update every weight. Backpropagation uses the chain rule to propagate gradient signals backward through the network — assigning a "blame score" (gradient) to each weight based on how much it contributed to the error.

Weights near the output receive large gradients. Weights deep in the network receive tiny ones — this is the vanishing gradient problem, and it's why residual connections matter so much.

Chapter 13

Gradient descent

Once gradients are computed, the optimizer nudges each weight in the direction that reduces loss: w ← w − lr × gradient. AdamW (used in most LLMs) adds momentum and adaptive learning rates per parameter.

Chapter 14

Decoder & autoregressive generation

The decoder generates text one token at a time. At each step it: (1) runs the full forward pass on all tokens generated so far, (2) takes the logits at the last position, (3) applies softmax and samples, (4) appends the new token and repeats.

The causal mask ensures position i can only attend to positions 0..i — no peeking at future tokens. This is what allows the model to be trained as a next-token predictor and used as a generator.

def generate(model, start, n=300, temp=0.8):
    idx = torch.tensor([encode(start)], dtype=torch.long)
    for _ in range(n):
        logits, _ = model(idx[:, -block_size:])
        logits = logits[:, -1, :] / temp     # last step, apply temp
        probs = F.softmax(logits, dim=-1)
        idx_next = torch.multinomial(probs, num_samples=1)
        idx = torch.cat([idx, idx_next], dim=1)
    return decode(idx[0].tolist())

Chapter 16

KV cache — fast inference

Without caching, generating token N requires recomputing K and V for all N−1 previous tokens — O(n²) operations total. With the KV cache, we compute K and V once per token and store them. Each new token only needs to compute its own Q and read the cached K and V.

2023 research: PagedAttention (vLLM)

Manages the KV cache like OS virtual memory — paging it in and out as needed. Enables 24× throughput improvement and running multiple users on one GPU.

Chapter 17

Scaling laws

Loss decreases predictably as model size and training data grow: L ∝ N^(−0.076) (Kaplan et al., 2020). The Chinchilla paper (Hoffmann et al., 2022) found the optimal training budget: tokens = 20× parameters. GPT-3 (175B params on 300B tokens) was heavily undertrained by this measure — the same compute could have trained a 67B model on 1.4T tokens and gotten better results.

Chapter 18

RLHF — aligning the model

A pretrained model predicts text well but doesn't follow instructions. RLHF (Reinforcement Learning from Human Feedback) aligns it in three phases:

Phase 1 — SFT: Fine-tune on ~13k human-written (prompt, ideal response) pairs.

Phase 2 — Reward model: Train a model to score responses using ~33k pairwise comparisons (A is better than B).

Phase 3 — PPO: Use the reward model as a signal to fine-tune via RL, with a KL penalty to prevent reward hacking.

2023 improvement: DPO

Direct Preference Optimization skips the reward model entirely — training directly on preference pairs. Simpler, cheaper, and widely adopted by 2024 (LLaMA-2-chat, Mistral-Instruct).

Chapter 20

How LLMs fail

Hallucination: The model cannot distinguish "frequently mentioned" from "factually true." Training objective is next-token prediction, not factual accuracy. Fix: RAG (retrieval-augmented generation), chain-of-thought, tool use.

Attention sinks: [BOS] token absorbs disproportionate attention in long sequences (discovered 2023). Fix: StreamingLLM keeps 4 "sink" tokens + sliding window → infinite context at constant memory.

Repetition loops: Entropy collapse — the model gets stuck in a high-probability loop. Fix: repetition penalty (1.1–1.3×), contrastive search, min-p sampling (2024).

Chapter 21

Complete MicroGPT — ready to run

Save this as microgpt.py, create an input.txt with any text, and run python microgpt.py. With 5000 steps it takes ~2 minutes on CPU and coherent patterns emerge by step 2000.

import torch
import torch.nn as nn
import torch.nn.functional as F

# ── hyperparameters ──────────────────────────────────────
block_size = 8;  batch_size = 4;  n_embed = 32
n_head = 4;  n_layer = 3;  lr = 1e-3;  max_iters = 5000

# ── data ─────────────────────────────────────────────────
text = open('input.txt', 'r').read()
chars = sorted(set(text));  vocab_size = len(chars)
stoi = {ch:i for i,ch in enumerate(chars)}
itos = {i:ch for ch,i in stoi.items()}
encode = lambda s: [stoi[c] for c in s]
decode = lambda l: ''.join([itos[i] for i in l])
data = torch.tensor(encode(text), dtype=torch.long)
n = int(0.9*len(data))
train_data, val_data = data[:n], data[n:]

def get_batch(split):
    d = train_data if split == 'train' else val_data
    ix = torch.randint(len(d) - block_size, (batch_size,))
    x = torch.stack([d[i  :i+block_size  ] for i in ix])
    y = torch.stack([d[i+1:i+block_size+1] for i in ix])
    return x, y

# ── model ─────────────────────────────────────────────────
class Head(nn.Module):
    def __init__(self, head_size):
        super().__init__()
        self.key   = nn.Linear(n_embed, head_size, bias=False)
        self.query = nn.Linear(n_embed, head_size, bias=False)
        self.value = nn.Linear(n_embed, head_size, bias=False)
        self.register_buffer('tril', torch.tril(torch.ones(block_size, block_size)))
    def forward(self, x):
        B,T,C = x.shape
        k = self.key(x);  q = self.query(x)
        wei = q @ k.transpose(-2,-1) * C**-0.5
        wei = wei.masked_fill(self.tril[:T,:T]==0, float('-inf'))
        wei = F.softmax(wei, dim=-1)
        return wei @ self.value(x)

class MultiHead(nn.Module):
    def __init__(self, n_heads, head_size):
        super().__init__()
        self.heads = nn.ModuleList([Head(head_size) for _ in range(n_heads)])
        self.proj  = nn.Linear(n_embed, n_embed)
    def forward(self, x):
        return self.proj(torch.cat([h(x) for h in self.heads], dim=-1))

class FFN(nn.Module):
    def __init__(self):
        super().__init__()
        self.net = nn.Sequential(nn.Linear(n_embed, 4*n_embed), nn.ReLU(), nn.Linear(4*n_embed, n_embed))
    def forward(self, x): return self.net(x)

class Block(nn.Module):
    def __init__(self):
        super().__init__()
        self.sa  = MultiHead(n_head, n_embed//n_head)
        self.ffn = FFN()
        self.ln1 = nn.LayerNorm(n_embed)
        self.ln2 = nn.LayerNorm(n_embed)
    def forward(self, x):
        x = x + self.sa(self.ln1(x))
        x = x + self.ffn(self.ln2(x))
        return x

class MicroGPT(nn.Module):
    def __init__(self):
        super().__init__()
        self.tok_emb  = nn.Embedding(vocab_size, n_embed)
        self.pos_emb  = nn.Embedding(block_size, n_embed)
        self.blocks   = nn.Sequential(*[Block() for _ in range(n_layer)])
        self.ln_final = nn.LayerNorm(n_embed)
        self.lm_head  = nn.Linear(n_embed, vocab_size)
    def forward(self, idx, targets=None):
        B,T = idx.shape
        x = self.tok_emb(idx) + self.pos_emb(torch.arange(T))
        x = self.ln_final(self.blocks(x))
        logits = self.lm_head(x)
        loss = None
        if targets is not None:
            B,T,C = logits.shape
            loss = F.cross_entropy(logits.view(B*T,C), targets.view(B*T))
        return logits, loss

# ── train ────────────────────────────────────────────────
model = MicroGPT()
optimizer = torch.optim.AdamW(model.parameters(), lr=lr)
for step in range(max_iters):
    if step % 500 == 0:
        model.eval()
        with torch.no_grad():
            losses = []
            for _ in range(50):
                xb,yb = get_batch('train')
                _,loss = model(xb,yb)
                losses.append(loss.item())
            print(f'step {step} | loss {sum(losses)/len(losses):.4f}')
        model.train()
    xb, yb = get_batch('train')
    _, loss = model(xb, yb)
    optimizer.zero_grad(); loss.backward(); optimizer.step()

# ── generate ─────────────────────────────────────────────
def generate(start="\n", n=300, temp=0.8):
    idx = torch.tensor([encode(start)], dtype=torch.long)
    for _ in range(n):
        logits, _ = model(idx[:, -block_size:])
        probs = F.softmax(logits[:,-1,:] / temp, dim=-1)
        idx = torch.cat([idx, torch.multinomial(probs, 1)], dim=1)
    return decode(idx[0].tolist())

print(generate())
