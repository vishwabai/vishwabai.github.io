Sets & Logic — the guest list and the bouncer

What you think

A set is basically a list — order matters, and you can repeat items.

What's actually true

A set only cares who's on it. {1,2,2} = {2,1} = {1,2}. No order, no duplicates, no exceptions.
🎟️

Analogy 1 — the guest list

A set is a party guest list. A name is either on it or it isn't — there's no "half on the list." That binary, all-or-nothing membership is the entire idea of a set.
🛂

Analogy 2 — the bouncer

Logic (AND, OR, NOT) is a bouncer's rulebook: "let them in if (on_list AND has_ticket) OR is_staff." Every access-control check you've ever coded is this bouncer, dressed up.
Formal definitions
A ∪ B = { x : x ∈ A or x ∈ B }   (union)
A ∩ B = { x : x ∈ A and x ∈ B }   (intersection)
A − B = { x : x ∈ A and x ∉ B }   (difference)
Aᶜ = { x ∈ U : x ∉ A }   (complement, relative to universe U)
|A| = cardinality (number of elements). |A ∪ B| = |A| + |B| − |A ∩ B|   (inclusion–exclusion, n=2)
De Morgan's laws: ¬(A ∧ B) = ¬A ∨ ¬B   and  ¬(A ∨ B) = ¬A ∧ ¬B
Inclusion–exclusion generalizes: for three sets, |A∪B∪C| = |A|+|B|+|C| − |A∩B| − |A∩C| − |B∩C| + |A∩B∩C| — add the singles, subtract the pairs, add back the triple overlap you subtracted too many times.
Worked example
U = {1,...,10}, A = {2,4,6,8,10} (evens), B = {2,3,5,7} (primes)
A ∩ B = {2} → the only even prime
A ∪ B = {2,3,4,5,6,7,8,10}, so |A ∪ B| = 5 + 4 − 1 = 8 ✓ (matches inclusion–exclusion)
Aᶜ = {1,3,5,7,9} (the odd numbers in U)

Showing: A and B as independent sets.

Reveal the why → why does logic even need symbols?

English is ambiguous — "or" sometimes means "pick one," sometimes "pick either or both." Logic symbols (∧ AND, ∨ OR, ¬ NOT) remove the ambiguity so a computer (which has zero common sense) can evaluate them with no guessing.

⚡ Common Sticking Point

People read "OR" the way English uses it at a restaurant — "soup or salad" means pick exactly one. But logical OR (∨) is inclusive: it's true if either is true, or both are. That's why "exclusive or" (XOR) needed its own name — it's the special case, not the default.
Explain it in your own words: what's the actual difference between a set and a list?
A list cares about order and allows repeats — [1,1,2] ≠ [2,1,1]. A set strips both away: it only records membership. {1,1,2} collapses to {1,2}, and {1,2} = {2,1}. Sets answer "is X in here?" — nothing about position or count.

Functions & Relations — vending machines vs. messy connections

What you think

A function is basically a formula, like y = 2x + 1.

What's actually true

A function is any rule where each input gives exactly one output — even a plain lookup table with no formula at all, like a phonebook (name → number).
🥤

Analogy 1 — the vending machine

Press B4, always get the same chips. Same input, same output, every single time. That reliability — not the formula — is what makes something a function.
🧵

Analogy 2 — relations are looser

A relation is just "these things are connected somehow," like a friendship web. One person can have many friends — relations don't promise "exactly one output." Functions are the strict, well-behaved subset of relations.
Formal definitions
f: A → B is a function if ∀a ∈ A, ∃! b ∈ B such that f(a) = b  (exactly one b, the "∃!")
Injective: ∀a₁,a₂ ∈ A, f(a₁) = f(a₂) ⟹ a₁ = a₂  (no two inputs share an output)
Surjective: ∀b ∈ B, ∃a ∈ A such that f(a) = b  (every output is hit)
Bijective: injective AND surjective  → f⁻¹ exists
Composition: (g ∘ f)(x) = g(f(x))  — apply f first, then g
Domain = legal inputs. Codomain = the declared output set. Range = outputs actually produced (range ⊆ codomain, not necessarily equal).
Worked example
f: ℤ → ℤ, f(x) = 2x
Injective? Yes — 2a₁ = 2a₂ forces a₁ = a₂.
Surjective onto ℤ? No — odd numbers like 3 are never hit; range = even integers only.
So f is injective but not surjective onto ℤ — not bijective unless we shrink the codomain to "even integers."

Mode: function (one arrow out of each domain dot).

Reveal the why → why does "exactly one output" matter so much?

If one input could give two different outputs, a program calling that "function" twice with the same argument could get two different answers — chaos for anything from a calculator to a database key lookup. Determinism is the whole point.

⚡ Common Sticking Point

People mix up range (outputs actually hit) with codomain (outputs that are allowed). A function ℕ→ℕ defined as "double it" has codomain ℕ, but its range is only the even numbers — the rest of ℕ is allowed but never visited.
Explain it in your own words: why is "vending machine" a fair analogy for a function but not for a general relation?
A vending machine guarantees one button → one snack, every time — that's the determinism a function requires. A general relation doesn't promise that: pressing B4 could dispense chips one time and soda the next, which is fine for a "relation" (just a connection) but breaks the contract of a function.

Combinatorics — counting without listing

What you think

Permutations and combinations are two unrelated formulas to memorize.

What's actually true

They're the same counting idea, split by one question: does order matter? That single question is the whole concept.
📸

Analogy 1 — lining up for a photo

Permutations are arranging people for a photo: Alice-Bob-Carol looks different from Carol-Bob-Alice. Order changes the result, so it counts separately.
🏀

Analogy 2 — picking a team

Combinations are picking 3 people for a team: {Alice, Bob, Carol} is the same team no matter what order you picked their names. Order is thrown away, so we divide it back out.
Formal definitions
Multiplication principle: if step 1 has n₁ choices, step 2 has n₂ choices, ..., total = n₁ × n₂ × ... × nₖ
Permutations: P(n,r) = n! / (n−r)!  (arrangements, order matters)
Combinations: C(n,r) = n! / (r!(n−r)!) = (ⁿᵣ)  (selections, order doesn't matter)
Permutations with repetition: nʳ  (each of r picks has n options, repeats allowed)
Binomial theorem: (x+y)ⁿ = Σₖ₌₀ⁿ C(n,k) xⁿ⁻ᵏ yᵏ
n! = n×(n−1)×...×1, with 0! defined as 1 so the formulas still work at the edges.
Worked example
A lock uses a 4-digit PIN, digits 0–9, repeats allowed → 10⁴ = 10,000 possible PINs.
A committee of 3 chosen from 8 people (order doesn't matter): C(8,3) = 8!/(3!·5!) = 56.
The same 3 people assigned to President/VP/Secretary (order matters): P(8,3) = 8!/5! = 336 = 56 × 3!

The multiplication principle: each choice branches the tree; count the leaves.

⚡ Common Sticking Point

The classic bug: computing a combination but forgetting to divide by r!, which silently counts every team multiple times — once for each way its members could've been ordered. If your answer for "pick a team" looks suspiciously large, you probably forgot the division.
Explain it in your own words: if nPr and nCr use almost the same formula, what's the one idea that separates them?
Permutations count arrangements where order matters, so AB and BA are different outcomes. Combinations count selections where order doesn't matter, so AB and BA are the same outcome — collapsed into one. Combinations = permutations ÷ r!, because r! is exactly the number of ways to reorder the r chosen items.

Counting without listing relies on one multiplication principle: multiply the number of choices at each step. Whether you then divide by r! depends entirely on whether order matters.

Graph Theory — maps of friendships

What you think

"Graph" means a bar chart or line chart, like in a spreadsheet.

What's actually true

In discrete math, a graph is just dots (vertices) and lines connecting them (edges) — a network, nothing about axes or numbers.
🧑‍🤝‍🧑

Analogy 1 — the friendship map

Each person is a dot. Draw a line between two dots if they're friends. That's a graph — your entire social network, literally.
🌳

Analogy 2 — the family tree

A tree is a special graph: connected, but with no way to loop back to an ancestor. Exactly one path between any two people — no shortcuts, no cycles.
Formal definitions
Graph G = (V, E)  — a set of vertices V and a set of edges E ⊆ V × V
Degree deg(v) = number of edges touching v. Handshake lemma: Σᵥ deg(v) = 2|E|
Path = sequence of distinct vertices, each connected to the next. Cycle = a path that returns to its start.
Tree: connected + acyclic ⟺ exactly |V| − 1 edges ⟺ exactly one path between any two vertices
Complete graph Kₙ: every pair of vertices connected → |E| = n(n−1)/2
BFS visits nodes in layers (queue, FIFO); DFS dives down one branch fully before backtracking (stack, LIFO). Both touch every reachable vertex exactly once — they differ only in the order.
Worked example
A graph has degree sequence [3,3,2,2,1,1]. Sum = 12 = 2|E| → |E| = 6 edges.
A tree with 7 vertices must have exactly 7 − 1 = 6 edges, regardless of its shape.

Reveal the why → why does BFS find the *shortest* path?

BFS explores everything 1 step away before anything 2 steps away, then everything 2 steps away before 3, and so on — like ripples spreading from a stone dropped in water. The first time it reaches a node is guaranteed to be via the shortest possible route.

⚡ Common Sticking Point

"Connected" does not mean "complete." Connected just means you can get from any node to any other, possibly through several hops. Complete means every node is directly wired to every other node. A long, thin chain of nodes is connected but nowhere close to complete.
Explain it in your own words: what makes a tree a special kind of graph, rather than just any graph?
A tree is connected (you can reach any node from any other) AND acyclic (no loops back to where you started). That combination guarantees exactly one path between any two nodes — which is why trees are the natural shape for hierarchies, file systems, and decision processes with no "going back."

Number Theory & Modular Arithmetic — clock math

What you think

"Mod" is just a leftover — the remainder you throw away after division.

What's actually true

Mod defines a whole wraparound number system — like a clock — used to build cryptography, hashing, checksums, and calendars. It's an arithmetic, not a scrap.
🕐

Analogy 1 — the clock

9 + 5 on a 12-hour clock isn't 14, it's 2 — the numbers wrap around. That's exactly mod 12 arithmetic: (9+5) mod 12 = 2.
⚛️

Analogy 2 — primes as atoms

Primes are the indivisible atoms of numbers. Every other whole number is built by multiplying primes together — there's exactly one "recipe" of prime ingredients for any number, which is why primes anchor cryptography.
Formal definitions
a mod m = the unique r ∈ [0, m−1] such that a = qm + r for some integer q
a ≡ b (mod m) ⟺ m divides (a − b)  ("a and b are congruent mod m")
gcd(a,b) = largest d dividing both a and b. Euclid's algorithm: gcd(a,b) = gcd(b, a mod b)
Fundamental Theorem of Arithmetic: every integer > 1 factors into primes in exactly one way (up to order)
Modular inverse: a⁻¹ exists mod m ⟺ gcd(a,m) = 1  (a and m are coprime)
This is the load-bearing wall under RSA encryption: pick two huge primes, multiply them — factoring the product back apart is what's computationally hard.
Worked example
gcd(48, 18) via Euclid: gcd(48,18) = gcd(18, 48 mod 18) = gcd(18,12) = gcd(12,6) = gcd(6,0) = 6
23 mod 7 = 2, since 23 = 3×7 + 2
60 = 2² × 3 × 5 — the unique prime factorization (Fundamental Theorem of Arithmetic in action)

⚡ Common Sticking Point

Negative numbers under mod trip almost everyone up. −3 mod 5 is not −3 — you keep wrapping forward (adding 5) until you land in range [0, m−1]. −3 + 5 = 2, so −3 mod 5 = 2. The wraparound works in both directions.
Explain it in your own words: why is a 12-hour clock a perfect real-world picture of "mod 12"?
A clock only has 12 distinct positions, and once you pass 12 you wrap back to 1 — the actual hour count (13, 14, 25...) doesn't exist on the face, only its remainder after dividing by 12 does. That's the literal definition of modular arithmetic: numbers collapse into a fixed, finite set of positions that repeat forever.

Proof by Induction & Recursion — dominoes and nesting dolls

What you think

Assuming the claim is true for n=k to prove it for n=k+1 is circular reasoning — it feels like cheating.

What's actually true

It's not circular — it's exactly how an infinite chain of dominoes is proven to fall. You're not assuming the whole claim; you're proving one domino topples the next, for an arbitrary k.
🁢

Analogy 1 — dominoes

Knock the first domino (base case). Show that any falling domino knocks the next one (inductive step). Together, that's proof the entire infinite line falls — without ever touching domino #847 directly.
🪆

Analogy 2 — nesting dolls

Recursion is a problem containing a smaller copy of itself, like a Russian doll. Open one, find a slightly smaller doll inside, until you hit the tiniest doll that doesn't open further — the base case.
Formal definitions
Weak induction: [P(1) true] ∧ [∀k, P(k) ⟹ P(k+1)] ⟹ ∀n ≥ 1, P(n) true
Strong induction: [P(1) true] ∧ [∀k, (P(1)∧...∧P(k)) ⟹ P(k+1)] ⟹ ∀n ≥ 1, P(n) true
Recursive definition: base case T(0) = c, plus recurrence T(n) = f(T(n−1), n)
Strong induction lets you assume the claim for ALL smaller values, not just k — essential for proofs like "every integer > 1 has a prime factorization," where you may need to drop to a much smaller case, not just k−1.
Worked example — geometric sum
Claim: 1 + 2 + 4 + ... + 2ⁿ = 2ⁿ⁺¹ − 1
Base (n=0): 1 = 2¹ − 1 = 1 ✓
Inductive step: assume true for k. Then 1+...+2ᵏ+2ᵏ⁺¹ = (2ᵏ⁺¹−1) + 2ᵏ⁺¹ = 2·2ᵏ⁺¹ − 1 = 2ᵏ⁺² − 1 ✓ — exactly the claim at k+1.

⚡ Common Sticking Point

The most common broken "proof": writing the inductive step but never actually using the inductive hypothesis — just restating the claim for k+1 without connecting it back to the k case. If your inductive step doesn't reference "assume true for k," it isn't induction yet.
Explain it in your own words: why isn't assuming "true for k" while proving "true for k+1" circular reasoning?
You never assume the full claim — you separately prove the base case is true on its own, and then prove a conditional statement: "IF it holds for some k, THEN it holds for k+1." Combining a true base case with a true conditional chain lets the truth cascade forward through every integer, without ever assuming the conclusion itself.

Boolean Algebra & Trees — where logic becomes hardware

What you think

Boolean algebra is unrelated abstract symbol-pushing, separate from "real" circuits.

What's actually true

It's literally the wiring diagram inside every chip you own. AND/OR/NOT gates are transistors arranged exactly like the truth tables from Chapter 1 — logic you already learned, now made of metal.
💡

Analogy 1 — gates are tiny decision-makers

An AND gate is a light controlled by two switches in series — both must be on. An OR gate is two switches in parallel — either one lights it. You've wired this in real life without realizing it was Boolean algebra.
🌲

Analogy 2 — decision trees are 20 Questions

A decision tree narrows down an answer with yes/no questions, branching deeper each time — exactly the tree structure from Chapter 4, now used to make a decision instead of just connect nodes.
Formal definitions
Boolean algebra: a set {0,1} with operations ∧ (AND), ∨ (OR), ¬ (NOT) obeying fixed axioms
Identity: A∧1=A, A∨0=A  |  Domination: A∧0=0, A∨1=1  |  Idempotent: A∧A=A, A∨A=A
Distributive: A∧(B∨C) = (A∧B)∨(A∧C)  |  De Morgan: ¬(A∧B)=¬A∨¬B, ¬(A∨B)=¬A∧¬B
XOR(A,B) = (A∨B)∧¬(A∧B)  |  NAND(A,B) = ¬(A∧B)  |  NOR(A,B) = ¬(A∨B)
NAND alone is "functionally complete" — every other gate (AND, OR, NOT, XOR...) can be built using only NAND gates, which is why real chips are often built almost entirely from one repeated gate type.
Worked example — truth table for (A∧B)∨¬C
A=1,B=1,C=0 → (1∧1)∨¬0 = 1∨1 = 1
A=0,B=1,C=1 → (0∧1)∨¬1 = 0∨0 = 0
A=1,B=0,C=0 → (1∧0)∨¬0 = 0∨1 = 1

The Pigeonhole Principle — too many socks, not enough drawers

What you think

This sounds too obvious to be real math — of course if you have more things than boxes, something doubles up.

What's actually true

That "obvious" idea proves surprisingly deep, non-obvious facts — like guaranteeing two people in any group of 367 share a birthday, with zero information about who they are.
🧦

Analogy 1 — socks in a drawer

If you own 10 pairs of socks (10 colors) but only have 9 drawer slots to sort them into by color, at least one slot must hold two different colors. You don't need to know which colors — the counting alone forces it.
🐦

Analogy 2 — pigeons and holes

The classic image: if 13 pigeons fly into 12 pigeonholes, at least one hole gets 2 pigeons. The principle doesn't say which hole — it just guarantees collisions exist once items outnumber containers.
Formal definitions
Pigeonhole principle: if n items are placed into m containers and n > m, some container holds ≥ 2 items
Generalized pigeonhole: if n items go into m containers, some container holds ≥ ⌈n/m⌉ items
⌈x⌉ is the ceiling function — round up to the nearest integer. ⌈13/12⌉ = 2.
Worked example
100 people, only 12 possible birth months → some month has ≥ ⌈100/12⌉ = ⌈8.33⌉ = 9 people sharing it.
5 points placed anywhere inside a unit square can always be split into 4 quadrant sub-squares — by pigeonhole, two points land in the same quadrant, and that quadrant has diagonal ≤ √2/2, bounding their distance.

⚡ Common Sticking Point

People expect the principle to tell them which container gets the collision, or how many extra items end up where. It promises neither — only that at least one collision exists somewhere once items > containers. It's a pure existence proof, not a construction.
Explain it in your own words: why does the pigeonhole principle prove something is true without ever identifying which item collides with which?
It's a counting argument, not a search. If you have more items than containers and tried to give every container at most one item, you'd run out of containers before items — a contradiction. That contradiction alone guarantees a collision exists, without ever needing to find or label it.

Equivalence Relations & Partial Orders — sorting vs. ranking

What you think

"Relation" is a vague catch-all word — any connection between things counts the same way.

What's actually true

Relations come in very different flavors depending on three properties (reflexive, symmetric, transitive) — and which ones hold completely changes what the relation is good for: grouping things, or ranking them.
👯

Analogy 1 — identical twins (equivalence)

"Has the same birthday as" splits everyone into clean, non-overlapping groups — everyone in a group shares the property, and nobody belongs to two groups at once. That's an equivalence relation: reflexive, symmetric, and transitive, all at once.
📶

Analogy 2 — height ranking (partial order)

"Is shorter than or equal to" lets you rank people, but two people of identical height aren't forced into the same "group" the way twins are — and you can't always compare every pair across unrelated categories. That asymmetry plus transitivity is a partial order.
Formal definitions
Reflexive: ∀a, (a,a) ∈ R  |  Symmetric: (a,b)∈R ⟹ (b,a)∈R  |  Antisymmetric: (a,b)∈R ∧ (b,a)∈R ⟹ a=b
Transitive: (a,b)∈R ∧ (b,c)∈R ⟹ (a,c)∈R
Equivalence relation = reflexive + symmetric + transitive → partitions the set into equivalence classes [a]
Partial order = reflexive + antisymmetric + transitive → a "≤"-like ranking (not all pairs need be comparable)
Total order = partial order where every pair IS comparable (e.g. ≤ on the integers)
A Hasse diagram draws a partial order with "higher = greater," omitting any edge implied by transitivity — only the direct, uncollapsible relationships are drawn.
Worked example
R = "has the same remainder mod 3" on {0,1,2,3,4,5,6}. This is an equivalence relation.
Equivalence classes: [0]={0,3,6}, [1]={1,4}, [2]={2,5} — three clean, non-overlapping groups.
By contrast, "⊆" on the power set of {1,2} is a partial order: {1} and {2} are both subsets of {1,2}, but neither {1}⊆{2} nor {2}⊆{1} holds — they're simply incomparable.

Mode: equivalence classes — clean, non-overlapping groups.

⚡ Common Sticking Point

"Divides evenly into" feels relation-like but is not symmetric (2 divides 4, but 4 doesn't divide 2) — so it can never be an equivalence relation, no matter how reflexive or transitive it is. People assume reflexive + transitive is "basically" an equivalence relation; symmetry is not optional, it's load-bearing.
Explain it in your own words: what's the single property that separates "sorting into groups" from "ranking in order"?
Symmetry. An equivalence relation is symmetric — if A relates to B, B relates back to A, which is exactly what lets things collapse into interchangeable groups. A partial order drops symmetry in favor of antisymmetry — A ≤ B and B ≤ A only when A and B are literally the same element — which is exactly what makes "ranking" possible instead of just "grouping."
