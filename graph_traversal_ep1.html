GRAPH TRAVERSAL
EP. 01
Graph Algorithms · Episode 1

Every graph is a set of connections.
How do you actually walk through one?

Eight rooms, connected by doors. No map. No labels on the doors telling you where they lead. Just: start somewhere, and visit every room you can reach.

The setup

A graph is just G = (V, E)

Adjacency list — how a computer sees it 

          

          
V = vertices (the rooms). E = edges (the doors). "Traversal" means: starting from one vertex, systematically visit every vertex reachable from it — touching each one exactly once.

          
but a computer can only look at one door at a time — so what rule decides which door it opens next?

        

      

    


    
    

      Depth-First Search · intuition
      
Rule one: keep walking forward. Only turn back at a dead end.

      

        

          

        

        

          
Think of a hedge maze. You pick a direction and commit to it — all the way to a dead end. Only then do you retrace your last few steps and try the next unexplored path.

          
You never re-plan from scratch. You just undo one decision at a time. That "undo" is the whole idea behind DFS — before we even give it a formal algorithm.

          
        

      

    


    
    

      Depth-First Search · recursive
      
The call stack is the "undo" mechanism

      

        

          

          
        

        

          

            dfs.py
            
def dfs(v, visited):
    visited.add(v)
    for u in adj[v]:
        if u not in visited:
            dfs(u, visited)   # recurse

          

          

            Call stack (implicit)
            

          

          
O(V + E) time — every vertex started once, every edge inspected once. O(V) space — one stack frame per vertex on the current path.

        

      

      

        RECAP
        Each call to dfs() remembers exactly where to resume — that's a stack frame doing the "undo."
        
but recursion depth is capped by your language's call stack — a chain of 200,000 vertices can crash a "correct" program. what do we do when the graph itself is the problem?

      

    


    
    

      Depth-First Search · iterative
      FILL
      
Make the stack explicit — and watch the order change

      

        

          

          
        

        

          

            dfs_iterative.py
            
def dfs_iter(start):
    stack = [start]; visited = set()
    while stack:
        v = stack.pop()          # take the TOP
        if v in visited: continue
        visited.add(v)
        for u in adj[v]:
            if u not in visited:
                stack.append(u)

          

          

            Explicit stack (array)
            

          

          

            Same reachable vertices — different visit order. A stack pops last-in-first. Pushing B then C means C is popped first — the reverse of what recursion did. To match recursion exactly, push neighbors in reverse.

      A limitation, made visible
      
DFS reaches every room. It doesn't promise the nearest route.

      

        

          

          
        

        

          RECAP
          
DFS from A reaches H — but by tunnelling through B, D, F, E, C first. Six doors, when a two-door route existed all along (A → C → H).

          GAP
          
DFS never "looks around" before committing — it only looks forward. what if, instead, we explored everything one step away before going further?

        

      

    


    
    

      Breadth-First Search · intuition
      FILL
      
Explore in rings, like ripples in a pond

      

        

      

      
Every room exactly one door away is visited together, before any room two doors away. No commitment to a single direction — the search grows outward evenly, like a wavefront.

      
    


    
    

      Breadth-First Search · formalized
      
A queue enforces "one ring at a time"

      

        

          

          
        

        

          

            bfs.py
            
def bfs(start):
    visited = {start}; dist = {start: 0}
    q = deque([start])
    while q:
        v = q.popleft()        # FRONT out
        for u in adj[v]:
            if u not in visited:
                visited.add(u)   # mark on enqueue!
                dist[u] = dist[v] + 1
                q.append(u)      # BACK in

          

          

            Queue (FIFO)
            

          

          
Mark visited the moment you enqueue, not when you dequeue — otherwise the same vertex can be queued twice. This is the #1 real-world BFS bug.

        

      

    


    
    

      Why BFS guarantees shortest hops
      
Distance = the ring you were first discovered in

      

        

          
Formal claim: for an unweighted graph, BFS discovers every vertex u at exactly dist(source, u) — the minimum number of edges.

          
Proof sketch, Feynman-style: ring 0 is just the source. Ring 1 can only contain vertices one door from ring 0 — there's no way to reach them faster, since ring 0 was everything closer. By induction, ring k+1 is built only from unvisited neighbors of ring k. You can never "skip ahead" — the queue physically won't let you.

        

        

          

            Complexity
            

              
TimeSpace

              
BFSO(V + E)O(V)

            

          

          

            RECAP
            
BFS guarantees the minimum-edge path. DFS doesn't — but DFS wasn't built for that job.

            GAP
            
so should we just always use BFS? what is DFS actually the right tool for?

          

        

      

    


    
    

      Choosing the right search
      
Same O(V+E) cost. Very different superpowers.

      

        

          

            
DFS is the right tool when...

            
you need to fully explore one branch before comparing it to another: detecting cycles, finding connected components, topological ordering, or backtracking search (Sudoku, maze generation, N-queens).

          

          

            
BFS is the right tool when...

            
"distance" or "fewest steps" matters: shortest path in an unweighted graph, minimum moves in a puzzle, checking if a graph is bipartite, or spreading outward level-by-level (social graphs, broadcast).

          

        

      

    


    
    

      Where this runs in production
      
Four systems you've already used today

      

        

          
          
Web crawlers

          
BFS from a seed URL. "Click depth" = BFS distance — pages found early rank as more important.

        

        

          
          
"2nd-degree connection"

          
LinkedIn / social graphs run BFS from you outward to label 1st, 2nd, 3rd-degree contacts.

        

        

          
          
Garbage collection

          
Mark-and-sweep GC does DFS/BFS from root objects. Anything unreached is memory to reclaim.

        

        

          
          
Maze generation & solving

          
Randomized DFS carves the maze (backtracking). BFS solves it — guaranteed shortest exit path.

        

      

    


    
    

      Things to know, before you move on
      
The cheat sheet

      

        

          

            
AlgorithmTimeSpaceGuarantees

            
DFS (recursive)O(V+E)O(V)reaches all, any order

            
DFS (iterative)O(V+E)O(V)same set, order may differ

            
BFSO(V+E)O(V)min. edge-count path

          

        

        

          
Gotcha 1 — mark BFS vertices visited at enqueue time, not dequeue, or duplicates flood the queue.

          
Gotcha 2 — naive iterative DFS visits neighbors in reverse order vs. recursion. Reverse the push order to match.

          
Gotcha 3 — on a directed graph, "reachable" is one-way. A can reach B without B reaching A — traversal alone can't detect that asymmetry; you need the direction of every edge.
