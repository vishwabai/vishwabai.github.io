From tokens to gradients · a working tour

A language model is a machine that turns text into numbers, multiplies matrices, and learns which multiplications to regret.

Everything a GPT does — every apparent flash of understanding — is built from one pipeline: tokenize, embed, attend, multiply, softmax, sample. And everything it knows was carved into its matrices by one signal: the gradient of a prediction error. This file walks the whole path, ending in real nanoGPT code, with live machinery you can poke at every stage.

live: a token stream flowing through embedding → attention → matmul → prediction
Stage 01 · The one job

An LLM does exactly one thing: predict the next token

Strip away the chat interface, the personality, the apparent reasoning. Underneath, a large language model is a function:

f(token₁, token₂, …, tokenₜ) → probability distribution over the next token

Given everything so far, it outputs a probability for every token in its vocabulary being next. GPT-2 has 50,257 tokens in its vocabulary, so its output is 50,257 numbers that sum to 1. Generation is just: predict, sample one token, append it, predict again. A thousand-word essay is a thousand runs of this single function.

Misconception alarm

"It looks up answers in a database." There is no database. At inference time an LLM is a frozen stack of matrices. The "knowledge" is stored as the values inside those matrices — the same way your knowledge of cycling is stored in synapse strengths, not in a filing cabinet in your skull.

Two analogies (keep both)

1 — The autocomplete that ate a library. Phone autocomplete predicts from your last few words using simple counts. An LLM predicts from thousands of tokens of context using ~billions of learned parameters. Same job, unrecognizably better execution.

2 — Compression. To predict the next token of "the capital of Tamil Nadu is ___" really well, you are forced to know the answer. Good prediction of all human text requires compressing the regularities of grammar, facts, code and logic into the weights. Prediction pressure is what smuggles understanding in.

Stage 02 · Tokens

Text becomes integers before anything else happens

Neural networks eat numbers, not letters. A tokenizer chops text into chunks — tokens — and maps each chunk to an integer ID from a fixed vocabulary. Modern models use Byte-Pair Encoding (BPE): start from raw bytes, then repeatedly merge the most frequent adjacent pair into a new vocabulary entry. Common words end up as single tokens; rare words shatter into pieces.

TOKENIZER BENCH
Type anything. A miniature BPE-style tokenizer (greedy longest-match over a small learned vocabulary) splits it and assigns IDs. Notice how common words survive whole while rare ones fragment.
Why not characters? Why not words?

Characters make sequences brutally long (attention cost grows with length²) and force the model to relearn spelling before meaning. Words explode the vocabulary (every typo, name and inflection is new) and can't handle anything unseen. BPE sits between: ~50k subword pieces, any string representable, frequent things cheap.

Side effects you've seen in the wild: models miscounting the r's in "strawberry" (it may be 1–2 tokens, letters invisible), and weaker arithmetic on unusually-chunked numbers.

From here on, the model never sees text again. The sentence above is now just a list like [791, 43678, 47349, ...] — and the next stage gives each integer a soul.

Stage 03 · Embeddings

Each token ID becomes a vector — a point in meaning-space

An integer like 1042 carries no meaning; ID 1042 is not "twice as much" as ID 521. So the first learned operation swaps each ID for a vector: a list of, say, 768 numbers. This is literally a table lookup into the embedding matrix WE, of shape vocab_size × n_embd — row i is the vector for token i.

x = WE[token_id]   # one row of a (50257 × 768) matrix → a 768-dim vector

Crucially, these vectors are learned, not designed. Training nudges them so that tokens used in similar contexts drift close together. Geometry starts encoding semantics: distance ≈ dissimilarity, and some directions become meaningful (the classic king − man + woman ≈ queen).

Position must be injected

Attention (Stage 06) treats its inputs as a set — it has no built-in idea of order. So we add a second lookup: a positional embedding WP with one learned vector per position. The vector entering the network is x = tok_emb + pos_emb. Same word, different slot → different vector. (Modern models often use RoPE — rotating query/key vectors by position-dependent angles — but nanoGPT's learned table is the clearest starting point.)

Checkpoint

You now have a (T × C) matrix: T tokens, each a C-dim vector (nanoGPT calls C n_embd). Every remaining stage is a transformation of this matrix. Ask yourself before scrolling: what operation could let these T rows talk to each other?

Stage 04 · The engine

Matrix multiplication: one operation, ~95% of all compute

Here is the operation that GPUs spend their lives on. Multiplying A (shape m×k) by B (shape k×n) gives C (m×n), where every output cell is a dot product: row i of A against column j of B.

Cij = Σd Aid · Bdj   # multiply pairwise, add up — that's all

Why this one operation, everywhere?

Because a matrix multiply is a batch of learned questions. Think of each column of the weight matrix W as a probe vector — a question. Computing x·W asks all n questions of vector x at once; each output number is "how strongly does x align with probe j?" Stack T token-vectors into X and X·W asks every question of every token simultaneously. That's why it parallelizes so perfectly on GPUs.

Analogy: a panel of judges

A weight matrix with 768 inputs and 3072 outputs is a panel of 3,072 judges. Each judge (column) has a fixed scorecard of 768 preferences. A token walks in; every judge scores it with a dot product. The output vector is the full score sheet. Training will turn out to be: adjusting the judges' scorecards after every wrong prediction.

Expert corner: where the FLOPs live

For a forward pass, a weight matrix of shape (k×n) applied to T tokens costs ≈ 2·T·k·n floating-point ops. Sum over all matrices in GPT-2 and you get the famous estimate FLOPs ≈ 2 · N_params · T per forward pass (≈6·N·T including backward). Attention's own T² term is small until contexts get long. LLM compute is matmul compute — which is exactly why "how does matmul learn?" is the right next question.

Stage 05 · The heart

How matrix multiplication becomes learning

A matrix multiply by itself is dead arithmetic. It becomes learning the moment three things are bolted onto it:

1. A loss — a single number measuring how wrong the prediction was.
2. A gradient — for every entry wij in every matrix, the derivative ∂loss/∂wij: "if I nudge this cell up a hair, does the error rise or fall, and how fast?"
3. An update rule — move every cell a small step against its gradient:

wij ← wij − η · ∂L/∂wij   # η = learning rate. Repeat a few billion times.

That's the entire trick. The matrix isn't "programmed"; it's eroded into shape by an endless stream of tiny regret-driven corrections. Each cell only ever follows a local rule — yet collectively the matrix organizes into something that predicts language.

Analogy: rain carving a valley

Each training example is one raindrop. One drop moves almost nothing. But billions of drops, each following the local slope (the gradient), carve riverbeds into the landscape (the weights). Nobody designed the river's path — it is the accumulated memory of where the water needed to go. A trained weight matrix is a fossilized record of every prediction error it survived.

What just happened, precisely

For each character pair (c → n) in the corpus: forward: logits = W[c]; probs = softmax(logits); loss = −ln(probs[n]). Backward: the gradient of that loss w.r.t. the logits is beautifully simple: ∂L/∂logit_j = probs[j] − 1[j = n] — prediction minus truth. Update: W[c] −= lr · (probs − onehot(n)). The cell for the true next character gets pushed up; every rival gets pushed down, in proportion to how confidently wrong the model was. GPT training is this exact loop, with a transformer inserted between the lookup and the logits.

Misconception alarm

"The model memorizes the training data." Look at the heatmap: 27×27 = 729 numbers cannot store the corpus. The matrix is forced to store statistics — reusable regularities — because it lacks the capacity to store instances. Scale that pressure up: GPT-2 saw ~40GB of text into 1.5B params (~6GB as float32, far less as information). Compression forces generalization. (Some verbatim memorization of highly repeated text does occur — but it's the exception the capacity budget permits, not the mechanism.)

Expert corner: why Adam, not plain SGD

Real training uses AdamW: it keeps a running mean (momentum, β₁=0.9) and running variance (β₂=0.95 in nanoGPT) of each parameter's gradient, and scales each step by mean/√variance. Effect: parameters with noisy or tiny gradients get adaptively larger steps; a heavy ball rolls through small dips. Plus weight decay (the W in AdamW) gently shrinks weights toward 0 — a prior that simple explanations are better. You'll see all of it in nanoGPT's configure_optimizers.

Stage 06 · Attention

Attention: tokens vote on which other tokens to read

So far each token is a lonely vector. But meaning is contextual — bank in "river bank" vs "bank loan" must end up as different vectors. Self-attention is the mechanism that lets every token rebuild itself as a weighted blend of the tokens before it. Three learned matrices project each token vector x into three roles:

q = x·WQ  # Query — “what am I looking for?”
k = x·WK  # Key — “what do I advertise?”
v = x·WV  # Value — “what do I hand over if chosen?”

Token i scores every earlier token j by dot product qᵢ·kⱼ — the same similarity measure from Stage 03. Softmax turns scores into weights, and the token's new content is the weighted sum of values:

Attention(Q,K,V) = softmax( Q·Kᵀ / √dk + mask ) · V

Three details, each load-bearing: Q·Kᵀ computes all T² scores as one matmul. √dk tames the dot products (a sum of d random terms has std ∝ √d; unscaled, softmax saturates and gradients die). The causal mask sets every future position's score to −∞ before softmax — token i may only read tokens ≤ i, because the model must work when the future genuinely doesn't exist yet.

Analogy: a silent library

Every earlier token sits in a library holding up a key card ("I'm a noun, singular, animate…") and clutching a value folder (its actual content). The current token walks in with a query card ("seeking: the noun this pronoun refers to"). It compares its query against every key, takes a softmax-weighted photocopy of the matching folders, and staples the blend to itself. Nobody speaks; it's all dot products.

Expert corner: multi-head, and what heads become

One attention pattern per layer is too little. So split the C=768 channels into n_head=12 heads of 64 dims; each head runs attention independently in its own subspace, then outputs are concatenated and mixed by WO. Heads specialize emergently: interpretability work (e.g. Anthropic's induction-head studies) finds previous-token heads, syntax heads, and induction heads that implement "…A B … A → predict B" — a learned copy-paste that's a core ingredient of in-context learning. Nobody assigned these jobs; gradient descent invented them.

Stage 07 · The block

The transformer block: communicate, then compute — and repeat

Attention lets tokens talk; the MLP lets each token think about what it heard. A transformer block wires them together with two stabilizers — residual connections and LayerNorm — and the whole model is just this block stacked N times (12 for GPT-2 small, 96+ for frontier models).

# one block, exactly as nanoGPT writes it (pre-LN):
x = x + attn( ln₁(x) )   # communicate: mix info across tokens
x = x + mlp( ln₂(x) )    # compute: process each token independently

The MLP is two matmuls with a nonlinearity between — expand to 4×C dims, apply GELU, project back:

mlp(x) = GELU(x·W₁ + b₁)·W₂ + b₂   # W₁: (768→3072), W₂: (3072→768) — ⅔ of all params live here
Why each piece exists

Residual (x + f(x)): the block computes a correction, not a replacement. Information flows through an untouched highway; gradients flow backward through it too, which is what makes 100-layer training possible. Think of the residual stream as a shared whiteboard each block reads and politely appends to.

LayerNorm: re-centers and re-scales each token's vector before each sub-block — keeping activations in the range where gradients are healthy, layer after layer.

GELU nonlinearity: without it, all those stacked matmuls would collapse into one big matmul (linear × linear = linear) and depth would buy nothing. The gentle curve between W₁ and W₂ is what lets the network compose genuinely new functions. The 4×-wide hidden layer acts like a key–value memory: research shows MLP neurons firing for specific concepts and facts.

Expert corner: the residual stream view

A productive mental model from interpretability work: the residual stream is a communication bus of width C. Attention heads and MLPs are peripherals that read from it (via their input matrices) and write to it (via their output matrices) in learned subspaces. Features are directions in this space; circuits are chains of components passing information through it. Depth = more read-modify-write cycles on the same bus.

Stage 08 · Output

Logits → softmax → a roll of the dice

After the last block, the final token's vector is multiplied by one last matrix — the unembedding / language-model head, shape n_embd × vocab_size. Out come 50,257 raw scores called logits. Softmax converts them to probabilities:

P(token j) = ezj/T / Σk ezk/T   # T = temperature

Then the model samples. Always taking the argmax makes text loop and flatten; sampling from the distribution keeps it alive. Temperature divides the logits first: T→0 sharpens toward greedy determinism, T>1 flattens toward chaos. Top-k keeps only the k highest logits before softmax, cutting off the long tail of nonsense.

"The model chooses its words." The model outputs a distribution; a random number generator outside the network picks the token. Same weights + same prompt + temperature 0 → same essay, forever. The "creativity" knob is literally a division performed on the logits.

Stage 09 · Training

The training loop: every token grades the model simultaneously

Now close the loop from Stage 05, at full scale. Take a chunk of real text of length T+1. Feed the first T tokens through the model. Thanks to the causal mask, position i's output is a prediction of token i+1 made without peeking — so one forward pass yields T predictions and T losses at once. The loss is cross-entropy: the average of −ln(probability the model gave the true next token).

L = −(1/T) Σi ln Pθ(xi+1 | x1..i)   # “how surprised were you, on average?”
# L = ln(50257) ≈ 10.8 → clueless · GPT-2 ≈ 3.1 · modern frontier ≪ that

Then backpropagation — the chain rule, applied backward through every matmul, softmax and GELU — computes ∂L/∂w for all parameters in one sweep, costing only ~2× the forward pass. The two rules worth memorizing:

# through a matmul Y = X·W :
∂L/∂W = Xᵀ·(∂L/∂Y)    # gradient of weights = input ⊗ output-error
∂L/∂X = (∂L/∂Y)·Wᵀ   # error flows backward through the same weights, transposed

# through softmax + cross-entropy (the miracle cancellation):
∂L/∂logitj = Pj − 1[j = target]  # prediction minus truth — as in the bigram lab
Analogy: blame accounting

The loss is a debt. Backprop is the auditor walking the books in reverse, splitting the debt among every weight according to the chain rule: “this cell contributed 0.0003% of the error.” The optimizer then collects — each weight pays its share by moving against its gradient. ∂L/∂W = Xᵀ·δ says blame lands where input was large AND output-error was large: exactly the cells that actively caused the mistake.

Expert corner: the three-phase life cycle

1 Pretraining — the above loop over trillions of tokens of internet text: weeks on thousands of GPUs; ~all of the capability. 2 Supervised fine-tuning — same loss on curated (instruction → good answer) pairs; teaches the assistant format. 3 RLHF / preference optimization — humans (or a reward model) rank outputs; the policy is nudged toward preferred behavior. Steps 2–3 barely change the weights (relatively) — they steer the giant prediction engine, they don't build it.

model.py · causal self-attentionstage 06
class CausalSelfAttention(nn.Module):
    def __init__(self, config):
        super().__init__()
        # ONE matrix computes Q,K,V for all heads at once: (C → 3C)
        self.c_attn = nn.Linear(config.n_embd, 3 * config.n_embd)
        self.c_proj = nn.Linear(config.n_embd, config.n_embd)  # W_O: re-mix heads
        self.n_head, self.n_embd = config.n_head, config.n_embd

    def forward(self, x):
        B, T, C = x.size()
        q, k, v = self.c_attn(x).split(self.n_embd, dim=2)   # each (B,T,C)
        # carve C channels into nh independent heads of size hs
        k = k.view(B, T, self.n_head, C // self.n_head).transpose(1, 2)  # (B,nh,T,hs)
        q = q.view(B, T, self.n_head, C // self.n_head).transpose(1, 2)
        v = v.view(B, T, self.n_head, C // self.n_head).transpose(1, 2)
        # THE equation: softmax(QKᵀ/√d + mask)·V  — fused Flash-Attention kernel
        y = F.scaled_dot_product_attention(q, k, v, is_causal=True)
        y = y.transpose(1, 2).contiguous().view(B, T, C)  # concat heads
        return self.c_proj(y)
the math it runsFor each head: att = softmax((q·kᵀ)·hs−½ + causal_mask), then y = att·v. The older nanoGPT versions spell it out — att = (q @ k.transpose(-2,-1)) * (1.0/math.sqrt(k.size(-1))), then att.masked_fill(bias==0, float('-inf')), softmax, att @ v. FlashAttention computes the identical result while never materializing the T×T matrix in slow memory — tiles it through on-chip SRAM.
model.py · MLP and Blockstage 07
class MLP(nn.Module):
    def __init__(self, config):
        super().__init__()
        self.c_fc   = nn.Linear(config.n_embd, 4 * config.n_embd)  # expand ×4
        self.gelu   = nn.GELU()                                     # the nonlinearity
        self.c_proj = nn.Linear(4 * config.n_embd, config.n_embd)  # project back
    def forward(self, x):
        return self.c_proj(self.gelu(self.c_fc(x)))

class Block(nn.Module):
    def __init__(self, config):
        super().__init__()
        self.ln_1, self.attn = nn.LayerNorm(config.n_embd), CausalSelfAttention(config)
        self.ln_2, self.mlp  = nn.LayerNorm(config.n_embd), MLP(config)
    def forward(self, x):
        x = x + self.attn(self.ln_1(x))   # communicate  (+ residual highway)
        x = x + self.mlp(self.ln_2(x))    # compute      (+ residual highway)
        return x

model.py · the GPT itselfstages 03 + 08 + 09
class GPT(nn.Module):
    def __init__(self, config):
        super().__init__()
        self.transformer = nn.ModuleDict(dict(
            wte = nn.Embedding(config.vocab_size, config.n_embd), # token table   (S03)
            wpe = nn.Embedding(config.block_size, config.n_embd), # position table(S03)
            h   = nn.ModuleList([Block(config) for _ in range(config.n_layer)]),
            ln_f= nn.LayerNorm(config.n_embd),
        ))
        self.lm_head = nn.Linear(config.n_embd, config.vocab_size, bias=False)
        # weight tying: the unembedding IS the embedding, transposed. Saves 38M
        # params in GPT-2 and helps: reading and writing share one meaning-space.
        self.transformer.wte.weight = self.lm_head.weight

    def forward(self, idx, targets=None):
        B, T = idx.size()
        pos = torch.arange(0, T, device=idx.device)
        tok_emb = self.transformer.wte(idx)      # (B,T,C)  IDs → vectors
        pos_emb = self.transformer.wpe(pos)      # (T,C)    where am I?
        x = tok_emb + pos_emb
        for block in self.transformer.h:         # N read-modify-write cycles
            x = block(x)
        x = self.transformer.ln_f(x)
        logits = self.lm_head(x)                 # (B,T,vocab) scores  (S08)
        loss = None
        if targets is not None:                  # training: T losses at once (S09)
            loss = F.cross_entropy(logits.view(-1, logits.size(-1)),
                                   targets.view(-1), ignore_index=-1)
        return logits, loss
the shape journey(B,T) ints → embed → (B,T,C) → 12 blocks, shape unchanged (residual stream!) → lm_head → (B,T,50257) → cross-entropy against the same text shifted left by one. The data is its own label — that's why pretraining scales: no human annotation needed.
generation + training loopstages 08 + 05
@torch.no_grad()
def generate(self, idx, max_new_tokens, temperature=1.0, top_k=None):
    for _ in range(max_new_tokens):
        idx_cond = idx[:, -self.config.block_size:]   # crop to context window
        logits, _ = self(idx_cond)
        logits = logits[:, -1, :] / temperature       # last position only (S08)
        if top_k: # keep k best, drown the rest
            v, _ = torch.topk(logits, top_k)
            logits[logits < v[:, [-1]]] = -float('inf')
        probs = F.softmax(logits, dim=-1)
        idx_next = torch.multinomial(probs, num_samples=1)  # the dice roll
        idx = torch.cat((idx, idx_next), dim=1)      # append, repeat
    return idx

# ---- train.py, reduced to its skeleton ----
for it in range(max_iters):

    optimizer.step()                  # AdamW: w ← w − lr·m̂/(√v̂+ε) − lr·λ·w

Three expert ideas worth owning

1 · The KV-cache — why generation is memory-bound

During generation, each new token needs attention over all previous keys/values — which haven't changed. So cache them. Cost per token drops from O(T²) recompute to O(T) reads, but the cache is huge: 2 · n_layer · n_head · head_size · T · bytes per sequence. At long context, moving this cache through memory bandwidth — not FLOPs — is the bottleneck. This is why GQA, paged attention, and quantized caches exist, and why your tokens/sec drops as a chat grows.

2 · Scaling laws — loss is a budget, not a mystery

Loss falls as a smooth power law in parameters N and tokens D. The Chinchilla analysis showed compute-optimal training wants roughly D ≈ 20·N — GPT-3 was undertrained for its size. Modern practice deliberately over-trains small models far past 20:1 because inference cost depends on N alone. Capability, to first order, is purchased in FLOPs.

3 · Emergence lives in the residual stream

Nothing in the code says "grammar module" or "arithmetic unit." Yet trained models contain induction heads, IOI circuits, French-detecting neurons. The lesson of Stage 05 at scale: a sufficiently large pile of matrices under sufficiently long prediction pressure organizes itself into algorithms. Mechanistic interpretability is the reverse-engineering of what gradient descent wrote.

Final misconception sweep

"It's just statistics, so it can't reason" and "it reasons, so it's not statistics" are both lazy. The truth is stranger: gradient descent on next-token prediction discovers circuits — real algorithms implemented in linear algebra — because algorithms predict better than lookup tables. Whether that constitutes "reasoning" is a definitional fight; that it's mechanistically more than n-gram counting is settled.

1 · A weight matrix "learns" because…
Learning = loss + gradient + update rule. The multiplication never changes; the numbers being multiplied do, each cell following ∂L/∂w downhill. (a) fails on capacity grounds — see the 27×27 bigram; (c) confuses the operation with its operands.
2 · Why divide attention scores by √dₖ?
The variance of a sum of d independent products is ∝ d, so magnitude ∝ √d. Huge logits → softmax outputs a near one-hot → derivatives ≈ 0 → the attention head stops learning. Softmax itself handles (a); (b) is irrelevant to a scalar divide.
3 · One forward pass over T tokens produces how many training signals?
Because position i provably can't see past i, its output is a legitimate prediction of token i+1. A 1,024-token chunk delivers 1,024 graded exam questions per pass — the efficiency that makes pretraining feasible.
4 · Remove every GELU from GPT-2. What remains?
Linear ∘ linear = linear (attention softmax adds some nonlinearity, but the MLPs — ⅔ of parameters — would collapse). Depth without nonlinearity buys nothing; the humble activation function is what makes 96 layers mean something.
5 · ∂L/∂logits under cross-entropy + softmax equals…
The exponentials and the log cancel into p − y: push up the truth, push down rivals in proportion to misplaced confidence. You watched this exact vector update the bigram heatmap in Stage 05. (c) is the loss, not its gradient.
