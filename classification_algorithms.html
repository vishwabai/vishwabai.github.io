The Core Idea

What is classification, really?

Every example lives somewhere in feature space. The job is to find the shape that separates the groups.

Definition
f : ℝⁿ → { 0, 1, ... , k }Map a point's features to a class label
Why this equation?
Why frame it this wayTreating classification as learning a function lets us reuse all of calculus and optimization — we can measure exactly how often f(x) disagrees with the truth, and adjust parameters to reduce it.
Real-world useEvery "which bucket" decision fits this mold: spam vs. not spam, tumor malignant vs. benign, loan approve vs. deny.
Legend
class A class B boundary

Binary — 2 classes (spam / not spam).

Multi-class — 1 label from k options (digit 0–9).

Multi-label — several labels at once (a movie can be both "comedy" and "romance").

Foundations · Model Complexity

Underfit, just right, or overfit?

The central tension in every model: too simple misses the pattern, too complex memorizes the noise.

The Math
Err(x) = Bias² + Variance + σ²Expected test error splits into three parts
Why this equation?
Why it's built this wayExpand E[(y − f̂(x))²] algebraically and it splits exactly into these three non-negative terms — there's no way to make all three zero at once, which is why there's always a trade-off.
Real-world useDiagnoses whether a model needs more data (fixes variance) or a richer model (fixes bias) — the first question to ask when accuracy plateaus.

Bias: error from a model too simple to capture the pattern (underfit).

Variance: error from a model so flexible it reacts to noise (overfit).

σ² (irreducible): noise no model can remove.

High bias fix: add features, use a more flexible model, lower regularization.

High variance fix: get more data, regularize, simplify the model, or ensemble (bagging).

Foundations · Validation

Train on some, test on the rest

Never grade a model on the questions it already saw the answers to.

The Math
CV error = (1/k) Σ errorᵢAverage the held-out error across all k folds
Why this equation?
Why it's built this wayOne test score is a single noisy sample. Averaging k independent estimates shrinks that noise, the same way averaging k coin flips gives a steadier read on the true bias of the coin.
Real-world useFairly comparing two models or hyperparameter settings before committing one to production.

A single 80/20 split gives one noisy estimate. k-fold CV rotates the held-out slice k times and averages — a steadier read on generalization.

Typical splits: 70/30 or 80/20 train/test; k = 5 or 10 for cross-validation.

Stratified split: preserve each class's proportion in every fold — crucial when classes are imbalanced.

Foundations · Preprocessing

Feature scaling

A feature measured in thousands can silently drown out one measured in single digits.

Standardize
x' = (x − μ) / σZero mean, unit variance — the common default
Why this equation?
Why it's built this waySubtracting the mean centers the data at 0; dividing by the standard deviation rescales every feature to the same "1-unit" spread, so no feature dominates a distance or gradient calculation just because of its raw units.
Real-world usePreparing mixed-unit data — age in years next to income in dollars — before feeding it to KNN, SVM, or a neural net.

Sensitive to scale: KNN, SVM, Logistic/Linear models, Neural Nets, SGD — anything using distance or gradients.

Doesn't care: Decision Trees and everything built from them (Random Forest, boosting) — splits are scale-invariant.

Standardization (z-score): centers at 0, unit variance — best when data is roughly Gaussian.

Min-Max normalization x'=(x−min)/(max−min): rescales to [0,1] — better when you need bounded ranges.

Algorithm 01 · Linear & Probabilistic

Logistic Regression

A straight line underneath, squashed into a probability on top.

The Math
z = w·x + b
σ(z) = 1 / (1 + e⁻ᶻ)Predict class 1 when σ(z) ≥ 0.5
Why this equation?
Why it's built this wayWe want a probability, but wx+b ranges over all real numbers. The sigmoid is the inverse of the log-odds (logit) function — exactly the transform that turns an unbounded score into a valid 0–1 probability.
Real-world useCredit scoring and medical risk models, where you want a calibrated probability of default or disease — not just a yes/no label.

The line score z can be any number. The sigmoid curve squeezes it into (0, 1) — a probability.

Where the surface reads exactly 50% is the decision boundary — still a straight line.

Pros: fast, interpretable coefficients, outputs calibrated probabilities.

Cons: only draws linear boundaries — needs engineered features for curved patterns.

Algorithm 02 · Instance-Based

K-Nearest Neighbors

No training. Just ask the neighbors what they are.

The Math
ŷ = mode { yᵢ : xᵢ ∈ Nk(x) }Majority label among the k closest points
Why this equation?
Why it's built this wayIf nearby points in feature space tend to share a label — a reasonable assumption for most real data — then the label of your closest neighbors is the most direct evidence available with zero training.
Real-world useRecommender systems ("customers similar to you bought…") and quick prototyping when you don't have time to train a model.

Store every training point. For a new point, find the k closest ones and let them vote.

Lazy: all the "work" happens at prediction time, not training time.

Choosing k: small k → jagged, overfit boundary; large k → smoother, can underfit. Usually tuned via cross-validation.

Curse of dimensionality: distances stop being meaningful in very high-dimensional feature spaces.

Algorithm 03 · Margin-Based

Support Vector Machine

Not just any separating line — the one furthest from both sides.

The Math
min ½‖w‖²
s.t. yᵢ(w·xᵢ+b) ≥ 1Margin width = 2 / ‖w‖ — maximize it
Why this equation?
Why it's built this wayThe distance from a point to the hyperplane w·x+b=0 is proportional to 1/‖w‖. So minimizing ‖w‖ while still classifying every point correctly is mathematically identical to maximizing the margin.
Real-world useText classification and bioinformatics, where the number of features is huge and a wide, robust margin matters.

Only the closest points — the support vectors — decide the boundary. Everyone else is irrelevant.

Like parking exactly between two cars: equidistant from both.

Kernel trick: swap the dot product for one computed in a higher-dimensional space (RBF, polynomial) — lets SVM draw curved boundaries without ever visiting that space explicitly.

C controls the margin/violations trade-off: small C → wider margin, more tolerance for mistakes.

Algorithm 04 · Tree-Based

Decision Tree

Ask one yes/no question at a time, and slice the space into boxes.

The Rule
if x₁ < t: left
else: rightRepeat recursively on each half
How A Split Is Scored
Gini = 1 − Σ pᵢ²p = fraction of each class in a box · 0 = pure, 0.5 = maximally mixed
Why this equation?
Why it's built this wayIf you picked a random point from a box and guessed its label using the box's own class proportions, Gini is the probability you'd be wrong. It's exactly zero when a box holds only one class.
Real-world useBuilding interpretable rule systems — loan-approval or triage rules a human can read line by line and audit.

Try every feature and every threshold t; keep whichever split drops the weighted Gini (or entropy) the most.

The boundary ends up axis-aligned — a staircase, not a diagonal.

Pros: interpretable — you can read the rules — and needs no feature scaling.

Cons: grows deep enough to memorize training data. Control it with max_depth, min_samples_split, or post-hoc pruning.

Algorithm 05–06 · Bagged Ensembles

Random Forest & Extra Trees

One tree overfits. A crowd of slightly-different trees generalizes.

The Math
ŷ = majority_vote( T₁(x), ..., Tₙ(x) )Each tree sees random rows & random features
Why this equation?
Why it's built this wayAveraging many noisy, independent estimators cancels out uncorrelated errors — the same reason polling many people gives a more stable read than asking just one.
Real-world useTabular business data — churn prediction, fraud scoring — where you need a strong, low-effort baseline fast.

Random Forest: random data samples + random feature subsets per split.

Extra Trees: also randomizes the split thresholds themselves — faster, even more diverse.

Out-of-bag (OOB) error: since each tree skips ~1/3 of the data, that held-out slice gives a free validation estimate.

Also yields feature importance — how much each feature improves purity across all trees.

Algorithm 07–09 · Probabilistic

Naive Bayes

Assume every feature votes independently — naive, but often right.

Bayes' Rule
P(y|x) = [P(x|y)·P(y)] / P(x)Pick the class y with the highest posterior
Why this equation?
Why it's built this wayBayes' theorem is just algebra for "flipping" a conditional probability — we know how likely certain words are given "spam," but what we actually want is how likely "spam" is given the words we just saw.
Real-world useSpam filters and sentiment classifiers, where you have a huge vocabulary and want a fast, easily-updated score.

Gaussian NB — continuous features (bell curves)

Multinomial NB — counts, e.g. word frequency

Bernoulli NB — binary presence / absence

Why it still works: even when features aren't truly independent, NB usually gets the ranking of classes right, which is all classification needs.

Extremely fast, needs little data, a strong baseline for text/spam classification.

Algorithm 10–11 · Generative Linear Models

LDA vs QDA

Model each class as a cloud. Same-shaped clouds → straight line. Different-shaped → a curve.

The Math
δₖ(x) = −½(x−μₖ)ᵀΣₖ⁻¹(x−μₖ) − ½log|Σₖ| + logπₖPredict the class k with the largest δₖ(x)
Why this equation?
Why it's built this wayUnder a Gaussian assumption, the class with the highest posterior probability is exactly the one with the largest δₖ(x) — this formula is just the log of the Gaussian density plus the log of that class's prior probability, with constants dropped.
Real-world useFace recognition (Fisherfaces) and small-sample settings where a low-variance, probabilistic linear model beats logistic regression.

LDA assumes both classes share one covariance Σ → the quadratic terms cancel out → the boundary is a straight line.

QDA lets each class keep its own Σₖ → the quadratic term survives → the boundary can curve.

More flexibility (QDA) needs more data to estimate safely — classic bias / variance trade.

Algorithm 12 · The Original Neuron

Perceptron

Guess. If wrong, nudge the line toward the mistake. Repeat.

The Update Rule
w ← w + η(y − ŷ)xOnly fires when the prediction is wrong
Why this equation?
Why it's built this wayWhen the prediction is correct, y−ŷ = 0 and nothing changes. When it's wrong, this rule nudges w in the direction of x — the smallest possible adjustment that would have fixed this exact mistake.
Real-world useMostly historical/pedagogical today — but it's the literal conceptual building block for how a single artificial neuron learns.

1957's answer to "can a machine learn a boundary?" Guaranteed to converge if the data is linearly separable.

Limitation: can't learn XOR or any non-linearly-separable pattern — a single line is all it has.

Stacking many perceptrons in layers is exactly what fixes this — see the next slide.

Algorithm 13 · Stacked Neurons

Neural Network (MLP)

Stack perceptron-like units in layers, and straight lines learn to bend.

The Math
h = φ(W₁x+b₁)
ŷ = φ(W₂h+b₂)φ = nonlinear activation (sigmoid, ReLU, ...)
Why this equation?
Why it's built this wayStacking two purely linear layers is still just one linear layer — matrix multiplications compose into another matrix. The nonlinearity φ is what stops the layers from collapsing and lets the network represent curves.
Real-world useImage recognition, speech-to-text — anywhere the true boundary between classes is highly non-linear.

Each hidden neuron is its own tiny linear boundary. Combined and bent by nonlinearity, they trace almost any shape.

Trained via backpropagation: the chain rule pushes the error gradient backward, layer by layer, to update every weight.

Flexible enough to overfit fast — dropout, weight decay, and early stopping keep it in check.

Algorithm 14 · Sequential Ensemble

Gradient Boosting

Build one small model. Then build another that fixes its mistakes. Repeat.

The Math
Fₘ(x) = Fₘ₋₁(x) + ν·hₘ(x)Each new tree targets the current residual error
Why this equation?
Why it's built this wayThis is gradient descent performed in "function space" instead of parameter space — each new tree hₘ is fit to point in the direction that most reduces the loss, and ν controls how big a step to take.
Real-world useSearch-result ranking and insurance risk pricing — tasks where squeezing out extra accuracy is worth the extra training time.

Unlike a forest (parallel, independent trees), boosting trees are built one after another — each correcting the last.

Key knobs: learning rate ν (smaller = slower but steadier), number of trees, tree depth.

Powerful but sequential — can't parallelize across trees, and too many rounds will overfit.

Algorithm 15 · Reweighted Ensemble

AdaBoost

Get a point wrong? It gets heavier — and harder to ignore next round.

The Math
αₘ = ½ ln( (1−errₘ) / errₘ )
ŷ = sign( Σ αₘhₘ(x) )Point size = sample weight; grows on mistakes
Why this equation?
Why it's built this wayαₘ falls out of minimizing exponential loss — it's exactly the log-odds of a learner being right vs. wrong, so more accurate learners automatically earn more say in the final vote.
Real-world useEarly real-time face detection (the Viola-Jones algorithm) — a cascade of simple weak classifiers combined exactly this way.

Weak learners (often 1-split "stumps") are combined, weighted by how accurate each one was.

Watch out: outliers and mislabeled points keep getting heavier weight — AdaBoost can overfit to noisy data.

Algorithm 16–18 · Boosting, Industrialized

XGBoost · LightGBM · CatBoost

Same core idea as gradient boosting — different engineering trade-offs.

XGBoost's Added Term
Obj = Σ l(yᵢ,ŷᵢ) + Σ Ω(fₖ)
Ω(f) = γT + ½λΣwⱼ²T = leaves, w = leaf weights — penalizes complexity directly in the loss
Why this equation?
Why it's built this wayAdding Ω(f) to the objective means the optimizer pays a price for building an unnecessarily complex tree, even if it fits the training data slightly better — Occam's razor baked directly into training.
Real-world useThe dominant algorithm in tabular-data Kaggle competitions and click-through-rate prediction at scale.

Plain gradient boosting only minimizes error. XGBoost adds Ω(f) to the objective itself, so every tree is fit to be accurate and simple.

LightGBM and CatBoost keep this same regularized-objective idea, and mainly change how the trees are grown.

XGBoost: the reliable all-rounder. LightGBM: fastest on huge tabular datasets. CatBoost: best out-of-the-box with categorical columns.

Algorithm 19 · Optimization Strategy

Stochastic Gradient Descent Classifier

Don't wait to see all the data — take a noisy step after every sample.

The Math
w ← w − η∇L(w; xᵢ, yᵢ)Gradient from one sample (or mini-batch), not all of it
Why this equation?
Why it's built this wayComputing the exact gradient over millions of rows is expensive. A single sample (or mini-batch) gives a noisy but unbiased estimate of that same gradient — on average, it still points downhill.
Real-world useTraining on streaming or web-scale data, where the full dataset never fits in memory at once.

The path zig-zags — noisier than full-batch descent — but each step is cheap, so it scales to huge datasets.

It's a training strategy, not a boundary shape — pairs with a linear model (logistic loss, hinge loss, ...).

Needs scaled features and a well-tuned learning rate — too high overshoots, too low crawls.

Learning-rate schedules (start high, decay over time) usually work better than a fixed rate.

Cross-Cutting Concept · Regularization

L1 vs L2 regularization

Penalize complexity itself, and the boundary calms back down.

The Math
L1: loss + λΣ|wᵢ|
L2: loss + λΣwᵢ²λ trades fit for simplicity
Why this equation?
Why it's built this wayBoth add a penalty proportional to weight size, so the optimizer must "pay" to keep a large weight. L1's sharp corner at zero makes it cheapest to snap unneeded weights to exactly 0; L2's smooth bowl only ever shrinks them.
Real-world useGenomics (Lasso isolates a handful of relevant genes from thousands) and economics (Ridge stabilizes correlated predictors).

L2 (Ridge): shrinks every weight smoothly toward zero.

L1 (Lasso): pushes weak weights to exactly zero — automatic feature selection.

Elastic Net blends both: λ₁Σ|wᵢ| + λ₂Σwᵢ² — sparse like L1, stable like L2.

Too much λ underfits; too little brings back overfitting — tune it via cross-validation.

Cross-Cutting Concept · Beyond Two Classes

One-vs-Rest vs One-vs-One

Most classifiers only know how to draw one line. Here's how they handle three classes or more.

The Math
OvR: k classifiers
OvO: k(k−1)/2 classifiersk = number of classes
Why this equation?
Why it's built this wayEvery classifier covered so far only knows how to separate two groups. These formulas just count how many two-group problems are needed to reconstruct a k-group decision — k single-vs-rest splits, or every pairwise combination.
Real-world useHandwritten digit recognition (10 classes) or product categorization (hundreds of categories) using an inherently binary model like SVM.

One-vs-Rest: train k binary classifiers, one per class against everyone else. Predict = highest confidence.

One-vs-One: train a classifier for every pair of classes, let them vote.

OvR trains fewer models but each sees an imbalanced problem (1 class vs. all others combined).

OvO trains more models, but each one only sees two classes — often cleaner boundaries.

Evaluation · Scoring The Line

Confusion matrix

Four ways a prediction can land — everything else is built from these four numbers.

The Math
Precision = TP/(TP+FP)
Recall = TP/(TP+FN)
F1 = 2·P·R/(P+R)Accuracy alone lies when classes are imbalanced
Why this equation?
Why it's built this wayF1 uses the harmonic mean, not the average, of precision and recall — the harmonic mean punishes a big imbalance between the two, so a model can't hide terrible recall behind great precision.
Real-world useMedical screening tests, where you must explicitly trade off false alarms (precision) against missed cases (recall).

Precision: of what I flagged positive, how much was right?

Recall: of everything actually positive, how much did I catch?

Accuracy paradox: Accuracy = (TP+TN)/total looks great even at 99% if positives are rare — a model that always says "no" can still score high.

Evaluation · Threshold Sweep

ROC curve & AUC

Slide the decision threshold from strict to lenient, and trace the trade-off.

The Math
TPR = TP/(TP+FN)
FPR = FP/(FP+TN)Plot TPR (y) against FPR (x) at every threshold
Why this equation?
Why it's built this waySweeping the decision threshold from 1 down to 0 and plotting TPR vs. FPR at every point shows performance across all possible cutoffs at once, instead of committing to a single one.
Real-world useComparing fraud-detection or medical-test models independent of where you'll eventually set the alert threshold.

The diagonal is a coin flip. The further the curve bows toward the top-left, the better the ranking — AUC is the area under it, one number for "how separable."

Under heavy class imbalance, ROC can look overly optimistic — a Precision-Recall curve is usually more honest there.
